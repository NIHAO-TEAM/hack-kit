# queue-ui

### Requirement: очередь удержания

#### Scenario: открыть очередь

- WHEN маркетолог открывает «Очередь»
- THEN сверху три числа с подписями, ниже полоса «удалит биллинг» по клиентам в окне ожидания, таблица отсортирована по ожидаемой потере по убыванию
- Тест: frontend/src/app/queue.test.tsx: «три числа с подписями и полоса «удалит биллинг»»

#### Scenario: сортировка

- WHEN маркетолог дважды нажимает заголовок «Баланс»
- THEN таблица сортируется по балансу сначала по убыванию, затем по возрастанию (первый клик по числовому столбцу — убывание, по ID и email — возрастание)
- Тест: frontend/src/app/queue.test.tsx: «двойной клик по «Баланс»: сначала убывание, затем возрастание, строки в этом порядке»

#### Scenario: нет оценки

- WHEN у клиента нет оценки или он потерян
- THEN строка внизу, вместо скора — «нет оценки» или «потерян» с причиной
- Тест: скриншоты 1440/820/390 (строки «Без оценки» и «Потерян» внизу; порядок даёт сервер, `customers-api`)

### Requirement: постраничный просмотр очереди

Очередь SHALL позволять просмотреть всех клиентов снимка, а не только первые 200.

#### Scenario: больше одной страницы

- WHEN в снимке больше клиентов, чем помещается на страницу (50)
- THEN под таблицей видно «Показаны 1–50 из N» и переход по страницам; номер страницы — в адресе (`?page=`)
- AND на последней странице видны последние клиенты в выбранной сортировке
- Тест: frontend/src/app/queue.test.tsx: «230 клиентов: страница 5 показывает строку 201+ и подпись диапазона»; «одна страница: переключателя нет»

#### Scenario: смена сортировки

- WHEN маркетолог на странице 3 меняет сортировку, фильтр или поиск
- THEN очередь открывается с первой страницы
- Тест: frontend/src/app/queue.test.tsx: «смена сортировки возвращает на первую страницу»; «страница за пределами total — первая»

### Requirement: группа «У биллинга»

Очередь SHALL показывать клиентов «к биллингу» не в основной таблице, а в свёрнутой группе под ней.

#### Scenario: данные организаторов

- WHEN маркетолог открывает очередь
- THEN клиента 5 нет в основной таблице
- AND под таблицей свёрнутая группа «У биллинга (1)»; раскрыв её, маркетолог видит клиента 5 и причину без денежного действия
- Тест: frontend/src/app/queue.test.tsx: «клиент к биллингу не в таблице очереди, а в свёрнутой группе»

#### Scenario: нет таких клиентов

- WHEN ни один клиент не помечен «к биллингу»
- THEN группы нет
- Тест: frontend/src/app/queue.test.tsx: «нет таких клиентов: группы нет»

#### Scenario: группа не загрузилась

- WHEN запрос группы вернул ошибку
- THEN вместо группы заголовок «У биллинга — не загрузилось» с повтором, очередь на месте
- Тест: frontend/src/app/queue.test.tsx: «ошибка группы: заголовок с повтором, очередь на месте»

### Requirement: выгрузка очереди

Над очередью SHALL быть кнопка «Скачать CSV» — ссылка на выгрузку с текущими поиском, уровнем и сортировкой.

#### Scenario: сортировка в ссылке

- WHEN маркетолог отсортировал очередь по email и нажал «Скачать CSV»
- THEN ссылка ведёт на `/api/v1/customers/export.csv` с `sort=email&order=asc`
- Тест: frontend/src/app/queue.test.tsx: ««Скачать CSV» ведёт на выгрузку с текущей сортировкой»

### Requirement: сортировка на планшете и телефоне

#### Scenario: планшет

- WHEN очередь открыта на 820 px
- THEN сортировку по ID, email, балансу, пополнениям, скору и потере можно выбрать в обе стороны элементами не меньше 44 px
- Тест: frontend/src/app/queue.test.tsx: «блок «Сортировка» для узкого экрана…»; frontend/src/pages/queue/ui/SortControl.test.tsx

# Архив изменения

Делается исполнителем в том же PR, последним коммитом перед ревью. Так ревьюер видит и код, и то, как меняется описание поведения системы, а после слияния ничего доделывать не нужно.

1. Все задачи `tasks.md` отмечены. Неотмеченная задача — в «Не сделано» описания PR с причиной.
2. Перенеси сценарии из `changes/<имя>/specs/<capability>.md` в `specs/<capability>/spec.md`:
   - ADDED — добавить требование;
   - MODIFIED — заменить требование целиком;
   - REMOVED — удалить требование.
   Рядом со сценарием — имя теста, который его держит.
3. Статус в `proposal.md` — `на ревью`.
4. `git mv changes/<имя> changes/archive/<имя>`.
5. Фронт: отметь пункты `frontend/CHECKLIST.md`, впиши имя изменения.
6. Коммит `<имя>: архив изменения, specs`.

«Найдено по ходу» остаётся в `proposal.md` и в описании PR: его прочитает пахан.

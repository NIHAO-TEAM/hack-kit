# Выполнение изменения

Исполнитель в routine идёт по `.github/agents/executor.md`, этот скилл — его рабочая часть. Человек в локальной сессии может вызвать скилл напрямую.

## Перед началом

- На PR стоит `go:<id>`, которую поставил человек. Если её нет, а это локальная сессия, человек в ней прямо сказал «делай» по этой папке. Иначе — остановись.
- Прочитай всю папку изменения, `AGENTS.md` части и скиллы, указанные в `design.md`.
- Работа идёт в ветке PR (`change/<имя>`), с влитым свежим `main`. Новых веток и PR нет.

## По ходу

1. Задачи — по порядку. Отметка `[x]` ставится сразу после проверки из строки задачи. Коммит на задачу, push каждые 2–3 задачи.
2. Нашлось вне объёма — в `proposal.md`, раздел «Найдено по ходу». Не делай.
3. Подход из `design.md` не работает — обнови `design.md` с причиной. Если меняется поведение из specs — `[needs-human]`.
4. Упал гейт — чини код. Ослаблять тест, линтер, сторожа или исключать правило в конфиге нельзя.
5. Защищённый путь задет по необходимости из `proposal.md` — делай; CI поставит `protected`, сливать будет человек.

## Перед ревью

- `make check` (backend), `pnpm check` (frontend) — зелёные локально.
- Фронт: скилл `frontend-design-review` — скриншоты и чек-лист в описании PR.
- Скилл `change-archive` — в том же PR.
- Описание PR по шаблону из `executor.md`, снять черновик.

# Предложение изменения

Код в этом скилле не пишется. Результат — папка `changes/YYYY-MM-DD-<имя>/` со статусом `черновик` и короткий отчёт человеку.

## Шаги

1. **Прочитай контекст:** `docs/case.md`, `docs/scale.md`, все `docs/adr/*`, относящиеся к делу `specs/*`, `AGENTS.md` затронутых частей и их скиллы. Для фронта — `frontend/CHECKLIST.md` и макет экрана.
2. **Проверь существующее.** Каждое утверждение о коде проверь по коду (поиск по использованиям). Чего не проверил — пиши «гипотеза».
3. **Спроси, если от ответа зависит поведение.** Один-три вопроса, до того как писать артефакты. Мелочь — допущение в `design.md` с пометкой [ПРЕДПОЛОЖЕНО].
4. **Скопируй `changes/_template/`** и заполни:
   - `proposal.md`: только то, что следует из запроса, кейса, specs или кода. Обязательно «Вне изменения:». Правка `api/openapi.yaml` помечается как задевающая фронт.
   - `specs/<capability>.md`: только наблюдаемое поведение, WHEN/THEN, без кода. Для изменённого требования — требование целиком в новом виде.
   - `design.md`: подход, отброшенные варианты, допущения с метками, ссылки на ADR. Если решение меняет ADR — явно сказать.
   - `tasks.md`: задачи на 15–60 минут, у каждой — чем проверить. Порядок: контракт → данные → логика → экран → готовность.
5. **Фронт.** Если изменение задевает экран, а макета на холсте нет — сначала макет (скилл `frontend-design-direction`, раздел «Макет экрана»), ссылка в `proposal.md`. Без макета предложение не отдаётся.
6. **Размер.** Больше 6 часов работы — раздели на несколько изменений и скажи об этом.
7. **Черновик PR.** Ветка `change/YYYY-MM-DD-<имя>`, коммит с папкой, черновик PR `change: <имя>` с меткой `change` и комментарием `[lead]` по шаблону из `.github/agents/lead.md` (кого предлагаешь исполнителем и почему).
8. **Отчёт человеку** на один экран: что предлагается, «вне изменения», открытые вопросы, задевает ли защищённые пути и контракт, ссылка на PR. Согласование — метка `go:<id>`, её ставит человек.

## Чего не делать

- Не расширять объём «заодно».
- Не писать раздел критериев приёмки — их роль играют сценарии specs.
- Не ставить статус `согласовано` и метку `go:*`: согласует человек.

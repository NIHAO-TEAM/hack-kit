# Признаки `funds`, `fail`, `susp`, `flight`, проверки качества данных и golden на наборе организаторов

## Зачем

Кейс: «Почему возникает риск?»; примеры — «На аккаунте недостаточно средств для ближайших продлений», «`prolong_wait`, особенно при отсутствии средств»; «При недостатке данных… явно указать отсутствие оценки» (`docs/case.md`). Критерий — «обоснованность модели». После этого изменения Go-модель совпадает с оракулом до цента на данных организаторов.

## Что меняется

- Четыре признака по `docs/model-rules.md`, правило 5, каждый — отдельный файл с регистрацией:
  - `funds` — не хватает средств на продления в ближайшие 7 дней («Нужно 1 444,90 € на 7 дней, на балансе 915,06 €»);
  - `fail` — доля несостоявшихся продлений («2 из 3 продлений не прошли»);
  - `susp` — услуга выключена клиентом, но оплачивается;
  - `flight` — доля баланса, доступного к выводу.
- Проверки качества данных — тоже плагины, на скор не влияют, видны в результате: `prolong_wait` старше 5 дней («статус устарел»), `suspended` с истёкшим сроком, `blocked` со сроком в будущем. Счётчики по каждой проверке — в сводке.
- Golden-тест: `testdata/golden/organizers.json` и четыре граничных снимка совпадают с Go-результатом — скор, уровень, состояние, `f` каждого признака, деньги клиента и сводка (без действий).

Вне изменения:
- Действия с ценой — `money-actions`.
- Отображение проверок качества — экран «Источник» (этап 5).

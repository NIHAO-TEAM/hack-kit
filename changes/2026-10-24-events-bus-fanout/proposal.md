# Шина событий без общей блокировки: копия списка подписчиков, счёт потерь, бенчмарк

## Зачем

Эксперт aéza: показать сильные стороны Go и большую нагрузку (ADR-0004, п. 6). Поток 2–3 тыс. событий (`events-stream-emulator`) идёт через `internal/platform/events.Bus`. Проверено по коду: `Publish` держит общий `sync.Mutex` на всё время рассылки всем подписчикам, а при переполнении буфера (16) молча выбрасывает самое старое событие — сколько потеряно, не видно ни в метриках, ни в логе. С ростом числа SSE-клиентов издатель (пересчёт, приём снимка) ждёт на этой блокировке.

## Что меняется

- Список подписчиков темы — неизменяемый срез под `atomic.Pointer` (копия при записи): `Publish` читает его без блокировки, `Subscribe`/`cancel` создают новую копию под мьютексом записи.
- Поведение для медленного подписчика прежнее (не блокирует издателя, теряется самое старое), но каждая потеря считается: `churn_events_dropped_total{topic}`; число подписчиков — `churn_events_subscribers{topic}`.
- Размер буфера задаётся при подписке (`SubscribeBuf`), по умолчанию прежние 16; SSE-потоку — больше, если бенчмарк покажет пользу.
- Бенчмарки `BenchmarkPublish{1,100,1000}Subs` и параллельный `BenchmarkPublishParallel` до и после; результат в `docs/load/2026-10-24-events-bus.md` с железом и командой.
- Тест гонок: публикация из 8 горутин при одновременной подписке и отписке 1 000 подписчиков, `-race`, ни одной паники «send on closed channel».

Вне изменения:
- Темы событий и их содержимое.
- Модули-подписчики (`analytics`, `retention`): их код не меняется, API `Subscribe` совместим.

- frontend: нет
- контракт `api/openapi.yaml`: нет
- защищённые пути: нет

## Связанные решения

- ADR-0004: бэкенд и нагрузка; улучшение подтверждается бенчмарком.
- Гейт не ослабляется: тесты пакета `events` остаются.

# Дизайн: сортировка по всему списку

## Подход

`comparator` возвращает ещё флаг `pinUnscored`: `true` только для `score` и `expectedLoss`. В `ListCustomers` ветка «неоценённые внизу» выполняется только при этом флаге; иначе — `cmpFn` с направлением и ID как вторичный ключ для всех строк.

Тест `TestListCustomersSorts` переписать: для каждого из четырёх обязательных полей и обоих направлений — полный ожидаемый порядок ID на `testdata` (выписать из данных организаторов, не из кода), плюс `level=lost` с `id desc` = `8,7,3,2`. Для `score`/`expectedLoss` — хвост `lost/unscored` внизу.

## Отброшенные варианты

| Вариант | Почему нет |
|---|---|
| Хвост всегда, внутри по столбцу | Человек выбрал сортировку всего списка: кейс требует сортировку по полю |

# Дизайн: axe в CI

## Подход

1. `a11y.spec.ts`: вход через API (`/auth/login`), cookie в контекст; тема — через переключатель в шапке (или `colorScheme` контекста при «Как в системе»). Ожидание данных — по роли таблицы / заголовку экрана, не `networkidle` (SSE держит соединение).
2. `AxeBuilder({ page }).withTags(['wcag2a', 'wcag2aa'])`, фильтр `serious` / `critical`. Вывод: `экран · тема · ширина · правило · селектор`.
3. `deploy-a11y.yml`: `workflow_run` по завершении `Deploy smoke` с `conclusion == success` на `main`, Firefox, `--retries=1`. Пакеты — как в `deploy-smoke.yml` (`@playwright/test@1.49.1`) + `@axe-core/playwright@4.14.0`.
4. Исправления контраста — в токенах темы, чтобы поправить все экраны разом.

## Допущения

- [ПРЕДПОЛОЖЕНО] Тест только читает прод (без эмулятора и правок данных): безопасно гонять после каждого выката.
- [ПРЕДПОЛОЖЕНО] Ширина 820 не проверяется отдельно: axe не зависит от ширины, кроме скрытых на телефоне элементов — 390 покрывает это.

## Риски

- Красный `deploy-a11y.yml` не гейт слияния (новый workflow после выката), а сигнал: так новое правило не блокирует ночную работу.

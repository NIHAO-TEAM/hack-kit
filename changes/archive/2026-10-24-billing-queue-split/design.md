# Дизайн: биллинг отдельно от очереди

## Подход

1. **Правило.** `toBilling.Applies` смотрит на услуги со статусом `prolong_wait` и `AutoProlong`, при `Funds.Have ≥ Funds.Need`, и требует у этой услуги транзакцию `Type == "prolong"`, `Status == "not_performed"`. В `CustomerCtx` транзакций нет [ПРОВЕРЕНО: `risk/registry.go:39`] — добавить `Transactions []Transaction` (все транзакции услуг аккаунта, уже собираются в `score.go:123` как `txByService`). Заголовок действия: «К биллингу: N продлений не прошли при достаточном балансе».
2. **Контракт.** Параметр `billing` (`enum: [exclude, only]`) у `GET /api/v1/customers`; `make generate`, типы фронта. `Row.Billing` уже есть (`openapi.yaml:484`).
3. **Список.** В `ListCustomers` фильтр по `Row.Billing` до сортировки и пагинации, вместе с `level` и `q`.
4. **Очередь.** Два запроса: основной (`billing=exclude`, с сортировкой и страницами из `queue-pagination`) и группа (`billing=only`, `limit` 200, та же сортировка). Группа скрыта при N = 0. Живое обновление обновляет оба.
5. **Тесты.** `risk`: клиент 5 — да; клиент 10 (`prolong_wait`, денег хватает, попыток нет) — нет; клиенты 2, 3, 7 (`deleted`/`blocked`) — нет; денег не хватает при `not_performed` — нет. `analytics`: `billing=exclude` на данных организаторов не содержит 5, `only` = [5], `total` верный.

## Отброшенные варианты

| Вариант | Почему нет |
|---|---|
| prolong_wait без попыток списания (клиенты 5 и 10) | Нет следа сбоя: биллинг мог ещё не пытаться; решение человека 24.10 |
| Скрыть совсем | Человек выбрал свёрнутую группу: клиент не теряется из вида |
| Фильтр на фронте по `row.billing` | Ломает `total` и пагинацию; сортировку и фильтры считает сервер |

## Допущения

- [ПРОВЕРЕНО] В наборе организаторов: `prolong` `not_performed` — 23, у клиента 5 услуга 15 `prolong_wait`, `autoProlong`, баланс 28657 центов, цена 297, два `not_performed`.
- [ПРОВЕРЕНО] Оракул (`tools/oracle`) `to_billing` не считает, golden действие не содержит — golden не меняется. Если `actions_golden_test` упадёт — проверить, не держит ли он старое условие, и сообщить.
- [ПРЕДПОЛОЖЕНО] `Funds.Have ≥ Funds.Need` — нынешняя проверка «денег хватает» на уровне аккаунта; оставляем её.

## Фронт

- Состояния группы: загрузка — скелет заголовка; ошибка — заголовок «У биллинга — не загрузилось» с повтором; N = 0 — группы нет.
- Роль: маркетолог, аналитик, jury.

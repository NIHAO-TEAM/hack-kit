# Дизайн: очередь в CSV

## Подход

1. Выборка — та же функция, что у `GET /customers` (фильтры, сортировка), без `limit/offset`. Запись потоком (`encoding/csv` с `Comma = ';'`), BOM первым.
2. Числа — из центов: `1234,56` без разделителя тысяч (Excel читает как число). Уровень и причина — те же подписи, что у фронта; если подписи только на фронте — перенести справочник на сервер не нужно: причина в API уже текстом, уровень — 4 подписи в коде выгрузки.
3. Маршрут `GET /api/v1/customers/export.csv` — литерал; проверить, что ServeMux не путает его с `/customers/{id}` (тест).
4. Кнопка: ссылка с текущими параметрами; cookie-сессия идёт сама. Bearer-вход (Swagger) — тот же путь.

## Допущения

- [ПРЕДПОЛОЖЕНО] Разделитель `;` и десятичная запятая — под Excel с русской локалью, главный инструмент маркетолога.
- [ПРЕДПОЛОЖЕНО] Если к моменту apply слит `retention-tasks-api`, фильтр `task` выгрузка тоже принимает (та же функция выборки), колонку задачи не добавляем.

## Риски

- 100k клиентов: потоковая запись без сборки всего файла в памяти; проверить временем на `load-k6` наборе.

## Решения по ходу

- Колонка «под угрозой €» из proposal убрана: у строки очереди (`CustomerRow`) такого поля нет, `atRiskCents` есть только в сводке. Добавлять поле в строку — вне объёма. Вместо неё — «Версия пересчёта».
- Параметры `sort`, `order`, `billing` в контракте выгрузки — просто строки (не enum): одинаковые enum у двух операций заставили oapi-codegen переименовать константы списка. Значения проверяет сервер, неверное — 400.
- Кнопка выгружает с поиском, уровнем и сортировкой экрана, но без `billing`: файл содержит и строки «к биллингу» (колонка «К биллингу»), а не только основную очередь. [ПРЕДПОЛОЖЕНО]
- Журнал: действие `customersExported`; текст поиска не пишется (в нём может быть email), только «задан».
- Имя файла: `churn-queue-<asOf пересчёта>.csv`; если сводки ещё нет — `v<версия>`.
- Ячейки, начинающиеся с `= + - @`, получают префикс `'` (защита от формул в Excel).

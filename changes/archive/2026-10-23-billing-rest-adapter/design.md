# Дизайн: Адаптер REST-биллинга: данные сами приходят из API

## Подход

- Сравнение — хеш тела; одинаковый — без записи.
- Таймаут запроса 10 с, повтор с экспоненциальной задержкой.

## Решения по ходу

- [ПРЕДПОЛОЖЕНО] Хеш последнего тела хранится в памяти. После рестарта сервера первый опрос пишет снимок один раз, даже если биллинг не менялся: сравнивать с базой по значению дороже и рискованнее (время, порядок строк).
- Контракт, добавления без поломки: `SourceStatus.polling` (нет поля — опрос не настроен) и `PUT /api/v1/source/polling {paused}` (роли как у остальных записей источника; 404, если `BILLING_URL` пуст). Нужны для «пауза до включения на экране» из `proposal.md`.
- Пауза ставится только ручным `PUT /source/snapshot`. Правки и эмулятор опрос не останавливают: они меняют данные в базе, хеш тела биллинга не затрагивают, поэтому опрос их не затирает, пока биллинг не отдал новое тело.
- Включение опроса (`paused: false`) забывает хеш: ближайший опрос возвращает данные биллинга поверх ручных.
- Пауза и запись ручного снимка идут под тем же замком, что запись опроса: опрос не затирает снимок, загруженный во время запроса к биллингу.
- Задержка между опросами после сбоя растёт вдвое на каждый подряд сбой, потолок 5 минут (или интервал, если он больше). Отдельных повторов внутри одного опроса нет.
- Сбой, битое тело и снимок, не прошедший проверку, одинаково не трогают данные и считаются в `churn_billing_poll_errors_total`; экран пишет «данные от HH:MM UTC».
- `mock-billing` — `busybox httpd`, отдаёт файл набора организаторов; в Compose и в прод-Compose он включается профилем `billing` (`COMPOSE_PROFILES=billing`, `BILLING_URL=http://mock-billing:8081/snapshot.json`). На проде по умолчанию выключен: включение — отдельное решение. Токен mock не проверяет.
- Задачи 1.1–1.3 закоммичены одним коммитом: код опроса, сбоев и паузы делит один файл `adapter.go`.

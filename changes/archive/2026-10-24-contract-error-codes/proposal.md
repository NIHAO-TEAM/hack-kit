# Swagger: коды ошибок, которые сервер реально отдаёт

## Зачем

Эксперт aéza: эндпоинты — «для удобства тестирования нами» (`docs/experts/2026-10-23-aeza-chat.md`). Жюри проверяет API по Swagger, а там нет ответов, которые сервер отдаёт: 429 на перебор пароля (`auth/http.go:176`, сценарий «перебор пароля» в `specs/auth`), ответ на слишком большой снимок (`source/http.go:76`, `MaxBytesReader`), 403 на запрос по cookie без CSRF (`specs/auth`, «cookie без CSRF»). Не задокументировано, это видно в первом же «пробуем сломать». Найдено по ходу `auth-sessions` (`csrfToken` / `429` в контракте). Критерий «архитектура»: контракт совпадает с поведением.

## Что меняется

- `POST /auth/login`: ответ 429 «слишком много попыток входа» (и `Retry-After`, если сервер его ставит).
- `PUT /source/snapshot`: ответ на превышение лимита тела — тот код, который сервер отдаёт сейчас (413 или 400 — проверить по коду), с описанием лимита.
- Запросы, меняющие данные, по cookie без CSRF: 403 с описанием «нужен заголовок X-CSRF-Token из ответа входа»; в описании схемы безопасности — откуда брать `csrfToken`.
- Контрактный тест: для этих случаев ответ сервера проверяется по `openapi.yaml` (код описан, тело — `Problem`). Новый путь без описанного кода ошибки ловится тестом.

Вне изменения:
- Поведение сервера — не меняется; если найдено расхождение, которое требует правки поведения, — в «Найдено по ходу», не в этом изменении.
- `501 NotImplemented` у путей — не трогаем.

## Затронутые части

- backend: контрактный тест (рядом с существующими тестами контракта / `apitest`)
- контракт `api/openapi.yaml`: да, только добавление ответов и описаний (не ломает)
- защищённые пути: да — `api/openapi.yaml`; причина: недостающие ответы ошибок
- зависит от: нет

# Экран «Источник»: данные, качество, правка услуги, эмулятор

## Зачем

Защита, шаг 3 «Изменить… данные»; кейс: `PUT /source/snapshot` «с автоматическим пересчётом»; эксперт: данные приходят из REST биллинга. Аналитику нужен экран, где видно, откуда данные и насколько им можно верить.

## Что меняется

- Шапка: версия снимка, `asOf`, когда загружен, источник (`seed`, `api`, `emulator`).
- Проверки качества: счётчики «ошибка данных: в ожидании оплаты дольше 5 дней» и др. из сводки.
- Правка одной услуги (статус, автопродление, срок) и аккаунта (баланс, бонус) — `PATCH /source/services/{id}`, `/accounts/{id}`.
- Эмулятор: «+24 часа», «пополнить», «включить автопродление», «сбросить» — с подписью «имитация биллинга».
- Загрузка файла снимка (`PUT /source/snapshot`) с понятными ошибками `422`.

Вне изменения:
- REST-адаптер — `billing-rest-adapter`.

## Затронутые части

- backend: `internal/source` (новый `patch.go`: `PatchService`, `PatchAccount`)
- frontend: `pages/source`, `entities/source`
- контракт `api/openapi.yaml`: добавления в этом PR, если нужны (без поломки)
- защищённые пути: нет
- зависит от: `design-tokens`, `billing-emulator`, `summary-metrics`

## Найдено по ходу

- Источник `emulator` в шапке не показан: контракт знает только `seed` и `api` (эмулятор пишет `api`). Добавить значение — отдельным изменением контракта.
- `SourceStatus.checks` сервер не заполняет; счётчики качества берутся из `qualityCounts` сводки.
- `TestReaderLoadsStandSeed` (`transactions_amount_check`) и `TestSettingsAPI` красные и без этого изменения (проверено на main).

# Дизайн: ключи SSO из выката

## Подход

1. Один скрипт `sso-env.sh <env-файл> <домен>`: для каждого ключа — если нет строки `^KEY=.` , удалить пустую `^KEY=` и дописать значение. Значения не печатаются.
2. Порядок выката: `deploy-k8s.yml` (`deploy.sh` → `sso-env.sh` → values → helm) → `deploy-ingress.yml` (Keycloak с теми же ключами). Секрет клиента в приложении и в realm совпадает с первого выката.
3. `OIDC_DISCOVERY_URL` пишется по-Compose (`http://keycloak:8080/…`): `deploy.sh` уже заменяет его на Service чарта `churn-keycloak`.
4. Проверка: `deploy-smoke.yml` — тест «Keycloak: discovery на /sso» зелёный; вход по SSO на проде вручную — шаги человеку.

## Допущения

- [ПРЕДПОЛОЖЕНО] Импорт realm при каждом старте (`Strategy: OVERWRITE_EXISTING` в логе) — значения в realm всегда равны `.env`.
- [ПРЕДПОЛОЖЕНО] Кнопка SSO в приложении (`sso-button-flag`) появляется по `OIDC_ISSUER_URL` — после выката она станет видна; проверить в дымовом тесте.

## Риски

- Кнопка SSO появится на проде: если Keycloak не поднимется, вход по паролю остаётся.

# Дизайн: flight — вес 0

## Подход

1. Сначала оракул: вес `flight` 0 в `oracle.py`, перегенерировать `testdata/golden` (`python3 -I tools/oracle/oracle.py` в режиме записи, как в `scoring-oracle`), затем `DefaultWeight()` = 0 и `go test ./internal/risk ./internal/app` против нового golden. Числа сервера и оракула должны совпасть до цента, руками golden не править.
2. Новые контрольные числа выписать из оракула одним списком в `design.md` («Найдено по ходу»): уровни клиентов, ожидаемая потеря портфеля, клиент 9, клиент 1 после `noauto` 0,85, эффект письма №1, действие клиента 9. Этим списком заменить числа в документах, specs, моках и e2e.
3. Таблица чувствительности в `model.md` — пересчитать (строка `flight`: 0 → 0,1).
4. Хранение настроек: проверить `model_settings` и `settings-api`. Если на проде лежит явный вес 0,15 — в выкате или вручную через `PATCH /model/settings` под аналитиком вернуть 0; способ записать в README для жюри не нужно, записать в `Найдено по ходу`.

## Отброшенные варианты

| Вариант | Почему нет |

## Допущения

- [ПРОВЕРЕНО] Признак не упоминается в ADR и `tests/invariants/`.
- [ПРЕДПОЛОЖЕНО] Уровни клиентов из `demo-script.md` («высокие 10, 5, 9 …») могут сдвинуться — это нормально, демо-сценарий переписывается под новые числа. Если уровень клиента 9 или 1 перестаёт подходить для шагов демо — сообщить в PR `[lead]`/человеку, не подбирать веса.

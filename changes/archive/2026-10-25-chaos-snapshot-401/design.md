# Дизайн: 401 после загрузки снимка

1. Воспроизвести с логами обоих подов и Traefik (`kubectl logs -n kube-system deploy/traefik`), `curl -v`.
2. Проверить гипотезу таймаута: локально `ReadTimeout=5s` и тело, которое читается 10 с, — что видит клиент.
3. Чинить причину, а не тест: дедлайн чтения на маршрутах приёма снимать через `http.ResponseController.SetReadDeadline(time.Time{})` в обработчике до чтения тела.

## Допущения

- [ПРЕДПОЛОЖЕНО] Снятие дедлайна на маршрутах приёма безопасно: доступ к ним только по токену источника или роли, размер тела ограничен `SNAPSHOT_MAX_BYTES`.

## Решения по ходу

- Проверено по коду: `PutSnapshot` уже сам задаёт дедлайн чтения `SNAPSHOT_BODY_TIMEOUT_SEC` (2 мин) через `ResponseController`, перекрывая `ReadTimeout` 30 с, — гипотеза 1 по коду не подтверждается. Единственное место, где сервер пишет 401 «нужен вход», — `auth.Middleware` без валидного токена; `SOURCE_TOKEN` один на обе реплики (общий секрет).
- Причину по коду не определить, воспроизвести нельзя: в среде исполнителя нет Docker и k3d. Чтобы следующий прогон `Deploy chaos` показал, кто вернул 401, `chaos.sh` теперь пишет код, заголовки и время ответа и при ошибке печатает логи обоих подов и Traefik. Исправление — после этого прогона.
- Прогон `Deploy chaos` 40144106844 (разбор лида): `PUT /source/snapshot` вернул 200 за 35.7 с, снимок записан один раз. 401 вернул следующий запрос — `POST /auth/login`: `deploy-chaos.yml` не передаёт `ADMIN_LOGIN`, в чарте его нет, `service.go` не создаёт учётку админа без логина. Гипотезы 1–3 опровергнуты, тест «тело дольше `ReadTimeout`» (п. 2.1 прежней редакции) не нужен.
- Исправление: `templates/secret.yaml` добавляет `ADMIN_LOGIN: admin`, если ключа нет в `secretEnv` (`hasKey`); значение из `secretEnv` на проде (`deploy.sh`) не перебивается. `existingSecret` не затрагивается. `chaos.sh` при отказе входа печатает понятную причину.

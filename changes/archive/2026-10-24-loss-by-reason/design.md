# Дизайн: потеря по причинам

## Подход

1. Найти в `backend/internal/risk` расчёт вклада признаков в риск услуги (тот, что идёт в карточку «причины по вкладу») и в `backend/internal/analytics` сборку сводки.
2. Распределение: для услуги с потерей `L` и признаками `i` с `wᵢ·fᵢ`, доля признака `= wᵢ·fᵢ / Σ wⱼ·fⱼ`; сумма долей в центах равна `L` (остаток — самому большому вкладу). Услуги без признаков сюда не попадают (их потеря нулевая).
3. Сводка суммирует по причинам и по клиентам, список упорядочен по потере, затем по названию.
4. Оракул: функция распределения в `tools/oracle/oracle.py` и golden-файл `testdata/golden/` на наборе организаторов; сумма по причинам равна 3 599,07 €.
5. Клиент: блок «Где теряем деньги» в `Summary`, названия причин — из `featureInfo` (подписи уже есть в модели); клик ведёт в очередь, если фильтр по причине уже поддерживается, иначе блок без ссылок.
6. Обновить `docs/model.md`: раздел «Потеря по причинам» с оговоркой про распределение по вкладу.

## Допущения

- [ПРЕДПОЛОЖЕНО] Пропорциональное распределение по вкладу — приближение; шумовое ИЛИ строго не раскладывается на независимые части. Это написано в подписи.

## Риски

- Расхождение суммы с итогом на копейки: покрыть тестом на нескольких снимках, включая крайние.

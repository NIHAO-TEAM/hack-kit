# Дизайн: лимит времени демо-сценария

## Подход

1. Открыть прогон 40114338443 (лог `Demo e2e`): тест ограничен 30 с, шаг потока ждёт до 180 с. Подтвердить, что в `e2e/playwright.config.ts` общего `timeout` нет.
2. В начале тела длинного теста вызвать `test.setTimeout(...)`; значение — запас над измеренным временем прохождения (взять из зелёного прогона), потолок 300 с. Короткий второй тест («карточка без CRM-цикла») остаётся со значением по умолчанию.
3. Прогнать `Demo e2e` через `workflow_dispatch` три раза подряд; записать в описание PR время каждого шага из отчёта (`--reporter=list`) и скорость потока (события в секунду) из итоговой таблицы панели.
4. Если шаг потока выходит за 180 с на раннере, не поднимать лимиты, а описать это в «Найдено по ходу» с числами.

## Допущения

- [ПРЕДПОЛОЖЕНО] Других причин красного нет: до таймаута тест доходит до шага потока; подтвердить по скриншоту `test-failed-*.png` из артефакта `demo-screenshots`.

## Риски

- Лимит слишком большой скрывает зависание: потолок 300 с и записанные времена шагов.

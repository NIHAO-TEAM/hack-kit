# Демо-сценарий под то, что покажем 25.10: без CRM, с деньгами по причинам, сравнением действий и устойчивостью

## Зачем

Защита по кейсу — полный сценарий из четырёх шагов (`docs/case.md`, «Защита»), и выигрывает тот, у кого он проходит без сбоя. После ADR-0004 продукт заметно поменялся: убран цикл задач (#139), добавлены потеря по причинам (#142), сравнение действий (#143), устойчивость к весам (#144), поток событий (#140). `docs/demo-script.md` и `e2e/tests/demo.spec.ts` надо сверить с текущим продуктом: каждый шаг, который мы покажем жюри, должен проверяться прогоном `Demo e2e`, иначе на защите он может сломаться незаметно.

## Что меняется

- `docs/demo-script.md`: живое демо на 5 минут по текущему продукту — очередь по потере → карточка (причины, «Что сделать» с ценой) → «Сводка» (где теряем деньги по причинам) → аналитик меняет вес, предпросмотр и устойчивость → у маркетолога очередь перестраивается без перезагрузки → «Источник»: поток 2 500 событий, итог «согласованность 0 центов» → `/metrics` и Grafana «Внутри сервиса». Запасной ход для каждого шага. Таблица «Вопросы жюри» — сверить формулировки с `docs/pitch.md`.
- `e2e/tests/demo.spec.ts`: шаг на каждую строку живого демо; удалить шаги удалённых экранов (задачи) как следствие ADR-0004, а не ослабление гейта; числа — из golden организаторов.
- Удалить из сценария то, чего в продукте нет.

Вне изменения:
- Видео (решение владельца 24.10: пока не делаем).
- Код продукта: если шаг демо не проходит — запись в «Найдено по ходу» и отдельный черновик фикса.

# Дизайн: признаки и golden

## Подход

- Каждый признак — файл `feature_<id>.go` с `init() { Register(...) }`, интерфейс и контекст — из `risk-core` (`registry.go`, `ServiceCtx`). Общие для аккаунта величины («нужно» и «есть» для `funds`) уже посчитаны в контексте ядром; признак только читает.
- Веса по умолчанию (`DefaultWeight`): `funds 0,70`, `fail 0,40`, `susp 0,35`, `flight 0,15` (`docs/model-rules.md`).
- Тексты причин — по-русски, с числами в евро и днях, без технических имён: шаблон в самом признаке.
- **Проверки качества** — три реализации `Check` из `risk-core` в файлах `quality_*.go` с `RegisterCheck` в `init()`; поля `ServiceResult.Quality` и `Summary.QualityCounts` уже объявлены ядром.
- **Golden:** `golden_test.go` читает `testdata/golden/*.json` и соответствующие `*.snapshot.json`, вызывает `Score` с `asOf` и настройками из golden, сравнивает: деньги — точно, скор — до 0,01, `f` — до 1e-6. Поле `actions` не сравнивается (его проверяет `money-actions`).

## Отброшенные варианты

| Вариант | Почему нет |
|---|---|
| «Баланс < цена» для `funds` | на данных организаторов не срабатывает ни разу (`01b.md`, п. 3) |
| Проверки качества как признаки с весом | испортили бы скор на синтетике; эксперту показываем их отдельно |

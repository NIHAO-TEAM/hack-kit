# Дизайн: Вход через OIDC (Keycloak с ключом доступа и TOTP) второй кнопкой

## Подход

- Сессия после OIDC — та же, что после пароля (`auth-sessions`).
- Realm импортируется при старте (`--import-realm`); пароли демо-пользователей — из окружения.
- SSO-учётка хранится в `users` с логином `sso:<preferred_username>` и хешем `!` (не распознаётся, пароль не подходит); роль обновляется при каждом входе. Префикс не даёт занять парольную учётку.
- Роль — из claim `roles` ID-токена (маппер realm-ролей в realm JSON) или `realm_access.roles`; через SSO выдаются только `marketer` и `analyst`, `jury` и `admin` входят по паролю.
- Состояние потока (state, nonce, PKCE-verifier) — в HttpOnly-cookie `oidc_flow` на 10 минут, путь `/api/v1/auth/oidc`.
- Библиотеки: `go-oidc` v3.11.0, `oauth2` v0.27.0 (последние, не требующие Go новее 1.24 из `go.mod`) [ПРОВЕРЕНО: сборка и тесты с фейковым IdP].

## Решения по ходу

- Keycloak 26.0, `start` с импортом realm; пользователь `secure` получает действия «настроить TOTP» и «ключ доступа» при первом входе. [ПРЕДПОЛОЖЕНО] Работу ключа доступа в браузере без Docker-демона в среде не проверить: проверит человек на стенде.
- Прод: Keycloak включается `COMPOSE_PROFILES=sso`, который `bootstrap.sh` дописывает в `.env`, только если памяти ≥ 3,5 ГБ (в proposal ≥ 4 ГБ, но MemTotal 4 ГБ VM показывает меньше). Новый workflow деплоя не нужен. Расхождение: порог 3,5 ГБ вместо 4 — выбрано, чтобы 4-гигабайтная VM проходила по `MemTotal`.
- Тесты callback — с фейковым IdP (`httptest`), не с Keycloak в testcontainers: нет Docker и дешевле для CI.

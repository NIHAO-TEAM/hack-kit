# Дизайн: сортировка очереди на узком экране

## Подход

1. Компонент `SortControl` (Mantine `Select` + `Button`/`ActionIcon` с подписью) в `pages/queue/ui`, виден через CSS-медиазапрос `max-width: 64em` (тот же порог, что прячет/перестраивает таблицу), чтобы не было расхождения с вёрсткой таблицы.
2. Состояние — те же `sort`/`order` в параметрах маршрута, что у заголовков; смена — сброс на первую страницу, как сейчас.
3. `.sort` — `min-height: 44px` в том же медиазапросе.

## Допущения

- [ПРЕДПОЛОЖЕНО] Подписи направлений — «по возрастанию» / «по убыванию»; для потери и скора по умолчанию «по убыванию».

## Риски

- `layout.spec.ts` ищет кнопки сортировки по имени в заголовках: если на узком экране заголовки скрыты, тест должен проверять новый блок. Правка теста — `e2e/`, защищённый путь; если она нужна — причина: тест проверяет устаревший элемент.

## Решения по ходу

- Проверено по CSS (1.1): до 64em `thead` спрятан (`clip-path`, 1×1 px), сортировка на планшете была недоступна — верно описание #127, а не «27 px» (это размер спрятанных кнопок). `layout.spec.ts` на main уже пропускает кнопки ≤2 px.
- [ПРЕДПОЛОЖЕНО] Поле выбирается через Mantine `NativeSelect` (нативный выбор на касании, 44 px); направление — отдельная кнопка с иконкой и текстом. Выбор поля ставит направление по умолчанию (`firstOrder`), как первый клик по заголовку.
- `.sort` в заголовках — `min-height: 44px` в медиазапросе ≤64em, на широком экране без изменений.
- Блок виден только когда есть строки очереди (в пустой выдаче сортировать нечего).

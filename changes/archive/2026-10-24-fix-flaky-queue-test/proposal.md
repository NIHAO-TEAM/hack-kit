# Нестабильный тест очереди: первый запуск экрана не успевает за 1 с

## Зачем

CI на `main` красный на `f520a82` (слияние #137) и ранее на `1878db5` (правка только документов): падает один тест `frontend/src/app/queue.test.tsx` — «клик по заголовку меняет sort и order в адресе, повторный — направление»: `Unable to find role="table" and name "Клиенты под риском оттока"`. На PR #137 и на соседних коммитах `main` тот же тест зелёный, код очереди не менялся, в DOM виден каркас приложения без таблицы — экран ещё грузится. Причина (гипотеза): это первый тест файла, первый рендер маршрута `/queue` идёт с загрузкой кода экрана, а `findByRole` ждёт по умолчанию 1000 мс; на загруженном раннере этого мало. Красный `main` пропускает выкат: `Deploy k8s` не запускается, пока CI не зелёный, и последние слияния (в том числе вход с орбитой перед сессией эксперта) не доезжают до прода.

## Что меняется

- В настройке тестов клиента (`vitest` setup) время ожидания асинхронных запросов Testing Library (`asyncUtilTimeout`) — 5000 мс вместо 1000. Проверки (что именно ищем и что ожидаем) не меняются, тесты не пропускаются, порог не снижается.
- Если после этого тест всё ещё нестабилен на повторных прогонах, исполнитель находит место, где первый рендер медленный, и описывает его в «Найдено по ходу».

Вне изменения:
- Код экранов, другие тесты и их проверки.

## Затронутые части

- frontend: файл настройки тестов (`vitest.setup` или аналог)
- контракт `api/openapi.yaml`: нет
- защищённые пути: нет
- зависит от: нет

## Связанные решения

- Правило: гейт не ослабляется — меняется только время ожидания, не условия проверки.

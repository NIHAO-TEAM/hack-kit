# Архитектура: модуль задач удержания в документах для жюри

## Зачем

Ночью появился модуль `internal/retention` (#112, #118): задачи, история, наблюдения биллинга, метрики (#123). В `docs/architecture.md` («Схема потоков», «Модули», «Безопасность») и README («Модель и архитектура», «Дополнительно») его нет. Жюри оценивает архитектуру и расширяемость по документам и по коду. Без описания непонятно, почему задачи живут отдельно от снимка и почему «продлил после контакта» не считается эффектом контакта.

## Что меняется

- `docs/architecture.md`:
  - «Схема потоков»: снимок → пересчёт → наблюдения по открытым задачам → SSE `tasks`.
  - «Модули»: `internal/retention` — задачи и история отдельно от сменяемого снимка, связь с клиентом по ID и email, `customerMissing`, оптимистичная блокировка `version`, одна открытая задача на клиента (уникальный индекс).
  - «Безопасность»: права на задачи по ролям, журнал без email и текстов заметок.
  - Новый раздел «Чего мы не утверждаем»: наблюдение ≠ причина, нет ROI контакта; что для этого нужно (история, контрольная группа).
- README: «Дополнительно» — строка «Работа с клиентами: задачи, сроки, напоминания, наблюдения биллинга, CSV, метрики задач в Grafana»; «Модель и архитектура» — ссылка на новый раздел.
- `docs/model.md`: абзац «Задачи не меняют модель» — скор и деньги считаются только из данных биллинга.

Вне изменения:
- Код — нет. Расхождения документа с кодом — в «Найдено по ходу».

## Затронутые части

- docs: `docs/architecture.md`, `docs/model.md`, `README.md`
- контракт `api/openapi.yaml`: нет
- защищённые пути: нет

# Дизайн: настройки модели

## Подход

- Чтение и запись — `model.Store` (`recalc-engine`), событие `model.changed` публикует `Store.Save`.
- `dryRun`: снимок через `source.SnapshotReader`, `risk.Score` с текущими и черновыми настройками, разница уровней и ожидаемой потери. `model` не импортирует `analytics`.
- Частичная правка сливается поверх текущих настроек.

## Решения по ходу

- **Границы модулей.** `model` не импортирует `risk` и `source` (depguard), поэтому ядро и снимок подключаются портами `model.Ports`, склейку делает `internal/app/settings.go` (как `Recalc`). `dryrun.go` держит только тип результата и порты; расчёт — `app.Diff` поверх `risk.Score`. Расходилось: «dryRun через `source.SnapshotReader`» в этом разделе — читает `source.Reader` из `app`.
- **Контракт.** В `PATCH` не было ответа `422` — добавлен (`UnprocessableEntity`); в `ModelSettings` добавлены необязательные `updatedBy`, `updatedAt` («кто и когда менял»). Это добавления, ломающих правок нет.
- **`asOfMode`.** Есть в контракте, ядро его не читает: хранится в теле настроек рядом с остальными, проверяется в `model` (`snapshot|server`), по умолчанию `snapshot`. [ПРЕДПОЛОЖЕНО] семантику режима даты задаст отдельное изменение.
- **Проверка полей.** `risk.Settings.Problems()` отдаёт нарушения по полям (`weights.<id>`, `thresholds.high`, `horizonDays`, `priceBasis`); `Validate()` строится на нём и ведёт себя как раньше. Неизвестный признак в `weights` — `422` (проверяет `model` по реестру признаков).
- **Неизвестное поле в теле** (не из контракта) — `400`, а не `422`.
- **Гонка двух правок.** Слияние читает действующую версию и пишет следующую; две одновременные правки разных весов могут затереть друг друга (последняя побеждает). Для демо одного аналитика приемлемо. [ПРЕДПОЛОЖЕНО]
- Автор версии — логин из сессии (`auth.LoginFrom`).

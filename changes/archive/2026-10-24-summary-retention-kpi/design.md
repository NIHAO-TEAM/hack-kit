# Дизайн: блок работы с клиентами в сводке

## Подход

1. Агрегат в `internal/retention` (тот же, что у сборщика метрик #123): открытые по статусу, просроченные, `customer_id` открытых задач, у которых клиент есть в снимке. Сводка складывает `expectedLossCents` этих клиентов из текущего результата модели и считает клиентов `high`/`medium` без открытой задачи.
2. Поле `retention` в схеме сводки — необязательное: при ошибке БД задач сводка отдаётся без него (не 500), фронт прячет блок.
3. Ссылки: `/tasks?filter=overdue`, `/queue?task=none&level=high` — параметры, которые уже читают экраны (#116, #117); если имена параметров в `main` другие — брать фактические.
4. Склонение «клиент/клиента/клиентов» — существующий `plural` фронта.

## Допущения

- [ПРЕДПОЛОЖЕНО] «Без работы» считается только для `high` и `medium`: низкий риск и потерянные — не задача маркетолога сейчас.

## Риски

- `TestMetricsMatchSummary`: сверка `/metrics` и сводки должна покрыть новый блок, а не сломаться от него.

## Решения по ходу

- Агрегат живёт в `internal/analytics/summary.go`, а не в `internal/retention`: `retention` импортирует `analytics`, обратный импорт — цикл. Источник тот же (`TaskSource.OpenTasks`), поэтому числа совпадают с `/metrics`. Выбрано по правилу 3.4 (меньше риска), контракт и критерии не затронуты.
- [ПРЕДПОЛОЖЕНО] «Клиенты в работе» считаются как клиенты с задачей, привязанной к строке снимка (тот же email) — как `churn_retention_expected_loss_in_work_cents`. Задачи клиента вне снимка остаются в счётчиках задач.

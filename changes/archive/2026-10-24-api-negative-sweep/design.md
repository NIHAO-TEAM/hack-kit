# Дизайн: проход по контракту

## Подход

1. Разбор `openapi.yaml` библиотекой, которая уже есть в `go.mod` (`kin-openapi` или то, чем генерируется код) — без новых зависимостей, если возможно.
2. Генератор кривых значений по типу параметра и схеме тела; набор детерминированный (таблица), плюс fuzz.
3. Сервер — `apitest` (как другие HTTP-тесты), реальная БД (`dbtest`).
4. Отчёт теста: операция, запрос, код — при провале.

## Риски

- Изменение параллельно правит обработчики, которые трогают другие изменения: только проверки ввода, конфликты — слиянием `main`.

## Решения по ходу

- Контракт и сервер расходились: коды `400` у ряда операций не описаны в `openapi.yaml`. Выбор: тест их не считает провалом (критерий — ни одного `5xx` и `problem+json`), а печатает список в лог; правка контракта вне объёма.
- `501` у `oidcLogin`/`oidcCallback` описан в контракте — допускается тестом только когда описан.
- Стенд прохода поднимает воркер пересчёта и грузит снимок организаторов, иначе ручки данных отвечают `503` «расчёт не готов» — это не кривой ввод.
- Субъекты: без сессии, `jury`, служебные токены источника и метрик.

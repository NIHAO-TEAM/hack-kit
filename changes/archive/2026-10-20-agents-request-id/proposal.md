# Правило backend/AGENTS.md: X-Request-Id вместо X-Correlation-Id

## Зачем

После изменения `request-id` (#6) API возвращает `X-Request-Id`, а `backend/AGENTS.md` по-прежнему требует `X-Correlation-Id`. Агенты, читающие правила, начнут писать код под заголовок, которого в API нет. Это же — тестовое изменение C для проверки ручного слияния правил процесса: `backend/AGENTS.md` входит в `manual-merge-paths.txt`, поэтому после APPROVED исполнитель **не сливает** PR, а пишет `[merge] ждёт человека`.

## Причина правки защищённого пути

`backend/AGENTS.md` — правила агентов (защищённый путь, `manual-merge`). Правка нужна, чтобы правило совпало с реализованным поведением; ослаблений проверок и ограничений нет.

## Что меняется

- В разделе «Правила кода» строка про `X-Correlation-Id` заменяется строкой про `X-Request-Id`: заголовок есть в каждом ответе (UUID), его выставляет промежуточный слой `withRequestID`, значение пишется в логи и события, в `problem+json` поле `correlation_id` равно ему.

Вне изменения:
- Код API, тесты, `api/openapi.yaml`.
- Перенос идентификатора в логи (появится вместе с логированием).

## Затронутые части

- backend: `AGENTS.md`
- frontend: нет
- контракт `api/openapi.yaml`: нет
- защищённые пути: да, `backend/AGENTS.md` (`manual-merge`)

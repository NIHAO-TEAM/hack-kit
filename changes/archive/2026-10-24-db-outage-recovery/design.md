# Дизайн: отказ базы под залпом

## Подход

1. Сначала прогон на текущем `main` без правок: что реально происходит (коды ответов, логи, состояние потока, рестарты) — в «Найдено по ходу».
2. Править только расхождения с ожидаемым поведением из proposal, по одному, с тестом: `pgconn`-ошибки соединения → `errDBUnavailable` → `503`.
3. Повтор пачки: 3 попытки с паузой 100 мс → 1 с → 5 с, затем ожидание `pool.Ping` до возврата; канал не принимает новые события сверх буфера.
4. Возраст данных: заголовок `X-Data-Age` или существующее поле версии в ответах чтения — по тому, что уже есть.

## Допущения

- [ПРЕДПОЛОЖЕНО] Отдавать последний готовый результат при недоступной базе допустимо: данные помечены возрастом, запись недоступна.

## Риски

- `docker pause` и `kill` дают разные ошибки драйвера — проверить оба.

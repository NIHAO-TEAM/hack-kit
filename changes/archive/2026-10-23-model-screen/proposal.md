# Экран «Модель»: веса и пороги с предпросмотром до сохранения

## Зачем

Кейс: «Настройка модели. Коэффициенты isk-score редактируются через панель»; защита шаг 3 «Изменить коэффициент… показать обновление» (`docs/case.md`).

## Что меняется

- Для каждого признака — ползунок веса [0, 1] с подписью смысла («80 % услуг в ожидании оплаты не продлят»); пороги высокого и среднего уровня; горизонт; `priceBasis`.
- При изменении (с задержкой 300 мс) — предпросмотр `dryRun`: «сменят уровень N клиентов, потеря ±X €».
- «Сохранить» — новая версия, очередь у маркетолога обновится сама; «Сбросить к умолчанию».
- Ошибки `422` — у поля. Версия и кто менял — в шапке.
- Доступно аналитику, `jury`, администратору; маркетологу — «Недостаточно прав».

Вне изменения:
- Ползунок «что если» прямо в очереди — этап 6 (`whatif-slider`).

## Затронутые части

- backend: нет
- frontend: `pages/model-settings`, `entities/model-settings`
- контракт `api/openapi.yaml`: нет
- защищённые пути: нет

## Найдено по ходу

- В `ModelSettings` нет поля «кто менял» — в шапке только версия; добавить в контракт, если нужен автор.
- Шкала порогов (0–1 или 0–100) в контракте не описана; backend использует 70/50.

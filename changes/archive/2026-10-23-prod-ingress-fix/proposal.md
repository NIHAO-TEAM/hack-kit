# Прод отвечает по HTTPS через раз: один вход на 80/443

## Зачем

Эксперт aéza проверяет «репо + публичный домен». 23.10 22:05 МСК из 6 TLS-подключений к `nihao-churn.duckdns.org:443` подряд 3 получили сертификат Let's Encrypt, 3 — «no peer certificate» [ПРОВЕРЕНО пахан, `openssl s_client`]. Сразу после выката `helm-k3s` (деплой 18:55 UTC). Гипотеза: 80/443 слушают одновременно Caddy из Compose (`prod-compose`) и Traefik из k3s (`helm-k3s`).

## Что меняется

- Диагностика: шаг в workflow деплоя печатает (без секретов) `ss -ltnp` для 80/443, `docker ps`, `kubectl get svc,ingress -A`.
- Остаётся один вход — Traefik в k3s (прод на чарте); Caddy и приложение из Compose прода останавливаются и не поднимаются деплоем Compose; `deploy.yml` (Compose) на проде выключен или переключён только на проверку.
- Проверка после выката: 20 HTTPS-запросов подряд к `/healthz` с проверкой сертификата — все 200, иначе откат и красный job.
- Если k3s нестабилен — наоборот: вход только Caddy, k3s без servicelb на 80/443; решение и причина — в «Найдено по ходу».

Вне изменения:
- Новые функции, Grafana, Prometheus.

# Гостевой вход: роль «гость» только для просмотра и кнопка на экране входа

## Зачем

Питч 25.10 проходит в большом зале, на слайдах QR на прод. Люди из зала открывают продукт, но данных для входа у них нет. Владелец (valotr0n, 25.10 11:50): «какая роль не сможет сделать что-то плохое, чтобы и обычные люди могли зайти и посмотреть продукт» → «да, делай viewer и кнопку гостя».

Проверено по коду (`backend/internal/auth/permissions.go`): ни одна роль не безопасна для зала. `marketer` берёт клиентов в работу и меняет задачи (`accessWork`); после `single-user-role` получает и `accessStaff` — веса модели, загрузку снимка, эмулятор. Один человек из зала сломает демо жюри. Шкала: «Вход и роли», «UX».

## Что меняется

- Новая роль **`viewer`** («гость»): все операции `accessAnyRole` — только чтение (очередь, карточка, сводка, «О модели», настройки модели без правки, `GET /events`). Никаких `accessWork`, `accessStaff`, `accessService`. Права проверяет сервер для каждой операции.
- Новый открытый запрос **`POST /api/v1/auth/guest`**: создаёт сессию служебного пользователя `guest` с ролью `viewer`, без пароля. Включается переменной `GUEST_LOGIN_ENABLED=true` (по умолчанию выключен, выключенный — `404`). Ограничение частоты — как у `login` (`429`).
- `GET /auth/config` отдаёт `guestEnabled`; экран входа показывает кнопку **«Посмотреть как гость»**, если вход гостя включён.
- В интерфейсе у гостя: разделы только для чтения; кнопки правки (взять в работу, применить веса, источник, эмулятор) не показываются; плашка «Гостевой вход — только просмотр»; разделы «Источник» и «Журнал» в меню скрыты.
- Прод: `GUEST_LOGIN_ENABLED=true` в values Helm-чарта.

Вне изменения:
- Остальные роли и их права (в том числе итог `single-user-role`).
- QR и слайды: QR уже ведёт на прод.

## Затронутые части

- backend: `internal/auth` (роль `viewer`, `isRole`, вход гостя, конфиг), миграция (роль `viewer` в `CHECK` таблицы пользователей), тесты прав
- frontend: `entities/session` (роль, подпись, права), `pages/login` (кнопка), меню, скрытие кнопок правки, плашка
- контракт `api/openapi.yaml`: да — `Role` + `viewer`, `AuthConfig.guestEnabled`, `POST /auth/guest`. Добавление, не ломающее; причина — слова владельца выше
- защищённые пути: `api/openapi.yaml` (контракт), `deploy/` (`GUEST_LOGIN_ENABLED` в values прода), `e2e/` — только если демо-тест проверяет список кнопок экрана входа; `tests/invariants/` — не трогаем: если сторож перечисляет роли, исполнитель ставит `needs-human`
- зависит от: `single-user-role`

## Связанные решения

- ADR-0001: роли организации. Добавляется роль только для просмотра — дополнение, не отмена; строка-дополнение в ADR-0001 (задача 4.1).
- Макет: нет [ПРЕДПОЛОЖЕНО — фриз, этап 9; кнопка в стиле существующей кнопки SSO].

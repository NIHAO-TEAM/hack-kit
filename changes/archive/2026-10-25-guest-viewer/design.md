# Дизайн: гостевой вход

## Подход

- `permissions.go`: `RoleViewer = "viewer"`; `isRole` включает `viewer`; `accessStaff`, `accessWork` его не включают — гость проходит только `accessAnyRole`. Таблица тестов прав: `viewer` получает `403` на каждую пишущую операцию и на `listAudit`, `getModelSensitivity`, `getEmulatorStream`.
- Миграция: `CHECK (role IN (..., 'viewer'))` в таблице пользователей (сейчас `20261023170100_service_tables.sql:21`).
- Пользователь `guest` с ролью `viewer` заводится при старте, если `GUEST_LOGIN_ENABLED=true` (как демо-учётки из `DEMO_*_PASSWORD`, `auth/config.go`), без пароля: вход по паролю для него невозможен.
- `POST /api/v1/auth/guest` (`accessPublic`): выключен — `404`; включён — сессия как у `login` (та же кука, тот же TTL), ответ `LoginResult`. Ограничение частоты — тот же лимитер, что у `login`, по адресу клиента.
- `AuthConfig.guestEnabled` (обязательное поле, `false` по умолчанию).
- Фронт: `Role` + `viewer`, подпись «гость»; `rights.ts` — гость видит очередь, карточку, сводку, задачи (чтение), «О модели», «Модель» (чтение); домашняя страница — `/queue`. Кнопки правки скрыты по тем же правам, что сейчас скрывают их у маркетолога. Плашка в шапке «Гостевой вход — только просмотр». Экран входа: кнопка «Посмотреть как гость» под формой, если `guestEnabled`.
- Values прода: `GUEST_LOGIN_ENABLED: "true"`.

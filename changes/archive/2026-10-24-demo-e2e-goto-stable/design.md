# Дизайн: устойчивые переходы в демо-сценарии

## Подход

1. Взять упавший прогон `Demo e2e` 40113127801 (артефакты `demo-screenshots`) и повторить локально или через `workflow_dispatch` с трассой (`--trace on`): понять, что происходит между `goto('/queue')` и `goto('/summary')` в Firefox.
2. Хелпер `gotoStable(page, path, ready)`: `goto(path)`, затем `await expect(ready).toBeVisible()` — для очереди это таблица «Клиенты под риском оттока», для сводки — заголовок «Сводка». Использовать между всеми подряд идущими переходами сценария.
3. Если после хелпера `goto('/summary')` всё ещё обрывается, проверить прямое открытие `/summary` вручную в Firefox (маршрут, редиректы, поток событий) и описать причину; чинить приложение только отдельной задачей и с тестом клиента.
4. Прогнать сценарий три раза подряд на чистом стенде (`workflow_dispatch`), результаты — в описании PR.

## Допущения

- [ПРЕДПОЛОЖЕНО] Сбой воспроизводится только в Firefox, потому что Chromium допускает прерывание навигации тише; проверить проект `chromium`, если он есть в конфигурации.

# Дизайн: дымовая проверка прода

## Подход

- `smoke.spec.ts` читает `E2E_BASE_URL` и необязательный `E2E_JURY_PASSWORD`; тесты со входом — `test.skip(!password)`.
- `deploy-smoke.yml`: `workflow_run` по `deploy.yml` и `deploy-k8s.yml` (только при `conclusion == success`) и `workflow_dispatch`; адрес — из переменной репозитория `PROD_DOMAIN`; ставит Firefox Playwright, прогоняет `smoke.spec.ts` с 2 повторами (сеть).
- Падение: `gh issue create` с меткой `prod-down` (если открытой нет — без дублей), ссылка на запуск.

## Отброшенные варианты

| Вариант | Почему нет |
|---|---|
| Гонять `demo.spec.ts` на проде | меняет данные прода и привязан к суммам сида без `SEED_STAND` |
| curl-проверки в `deploy.yml` | правка существующего workflow исполнителю запрещена; в браузере видно больше |

## Допущения

- [ПРЕДПОЛОЖЕНО] Секрет `E2E_JURY_PASSWORD` в репозитории заведёт человек (пароль `jury` из `~/churn/.env` на сервере); до этого работает открытая часть.
- [ПРЕДПОЛОЖЕНО] Метки `prod-down` нет — workflow создаёт её сам.

- Сеть от раннеров GitHub до прода — видно первым же запуском; повторы на сбой.

# Набор стенда: ручные аккаунты 1001+ для наглядного демо

## Зачем

Кейс разрешает тестовый набор, «по усмотрению команды расширенный для наглядности» (`docs/case.md`). Эксперт: устаревшие `prolong_wait` организаторов — ошибка генератора; для живого таймера окна спасения нужны свежие (`docs/experts/2026-10-23-aeza-chat.md`).

## Что меняется

- При `SEED_STAND=true` к набору организаторов добавляются 6 ручных аккаунтов с id от 1001 (`asOf` тот же, 2026-10-19T15:00Z): свежий `prolong_wait` за 2 д 07 ч до удаления; почасовой сервер без автопродления, истекает через 20 ч; клиент с низким риском; аккаунт без услуг («нет оценки»); бонус заблокирован при нехватке средств; всё в порядке, автопродление включено.
- Данные организаторов не меняются: golden `organizers.json` по-прежнему совпадает, для набора стенда — свой golden от оракула.

Вне изменения:
- Эмулятор и кнопка «сбросить» — `billing-emulator`.

## Найдено по ходу
- `deploy/bootstrap.sh` (защищённый путь) не знает `SEED_STAND`; чтобы включить стенд на проде, нужна строка `SEED_STAND=true` в `.env` — отдельным изменением или руками. В этом PR добавлена только строка в `.env.example`.
- Сид читает `SEED_STAND` в `source.seedBody` напрямую из окружения, как `SNAPSHOT_MAX_BYTES`.

# Сверка Go с эталоном на 300 тыс. клиентов: каждый цент, каждый уровень

## Зачем

Эксперту интереснее большие данные (ADR-0004, п. 6). Эталонный расчёт `tools/oracle/oracle.py` сверяется с Go только на golden-файлах (набор организаторов и стенд). На больших снимках (генератор `backend/tools/snapgen`) мы проверяем скорость, но не правильность: ошибка округления или гонка в параллельном пересчёте на 300k может не проявиться на 50 клиентах. Нужна дифференциальная проверка «Go = эталон» на большом синтетическом снимке, с записанным итогом.

## Что меняется

- Скрипт `tools/oracle/parity.sh`: `snapgen` делает снимок на N клиентов с фиксированным зерном → Go считает (тот же код, что пересчёт, без HTTP и БД) → `oracle.py` считает → сравнение по каждому клиенту: уровень, скор, ожидаемая потеря в центах, первое действие.
- Go-сторона — команда `backend/tools/snapcalc` (или флаг существующего инструмента), печатает построчно JSON по клиенту; без новых зависимостей.
- Итог — число клиентов, число расхождений (ожидаем 0), время Go и эталона — в `docs/load/2026-10-24-oracle-parity.md` для N = 10k, 100k, 300k.
- Быстрый вариант (N = 10 000) — Go-тест с тегом `parity`, запускается локально и в `make parity`; в обязательный CI не добавляется (Python и время), [ПРЕДПОЛОЖЕНО].
- Если расхождение найдено — запись в «Найдено по ходу» с id клиента и отдельный черновик фикса; эталон не подгоняется под Go.

Вне изменения:
- Формулы, веса, golden-файлы.
- Обязательные гейты CI.

## Затронутые части

- backend: `tools/` (инструмент расчёта), `Makefile` (цель `parity`)
- frontend: нет
- контракт `api/openapi.yaml`: нет
- защищённые пути: нет
- зависит от: нет

## Связанные решения

- ADR-0004: большие данные, числа только из замеров.
- ADR-0001: объяснимый скор; эталон — источник правды.

## Найдено по ходу

- Расхождений Go и эталона на 10k, 100k, 300k клиентов нет (`docs/load/2026-10-24-oracle-parity.md`).
- «Первое действие» из предложения заменено сверкой набора действий и лучшего действия: порядок списка у Go (по выгоде) и эталона (фиксированный) разный, числа те же. Решение — в `design.md`, «Решения по ходу».

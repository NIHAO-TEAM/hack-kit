# Проверка живости API: GET /healthz

## Зачем

Деплой и `scripts/smoke.sh` должны отличать живой API от упавшего. Это же — тестовое изменение для проверки цепочки hack-kit (предложение → `go:exec-1` → исполнитель → ревью → слияние).

## Что меняется

- `GET /healthz` отвечает `200` с телом `{"status":"ok"}` и `Content-Type: application/json`.
- Другие методы на `/healthz` получают `405`, в заголовке `Allow` есть `GET`.

Вне изменения:
- Проверка базы данных и зависимостей (`/readyz`) — отдельное изменение, когда появится база.
- Метрики и логирование запросов.

## Затронутые части

- backend: `cmd/api`
- frontend: нет
- контракт `api/openapi.yaml`: нет (файла в заглушке ещё нет)
- защищённые пути: нет

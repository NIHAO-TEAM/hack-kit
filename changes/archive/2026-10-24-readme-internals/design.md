# Дизайн: README по внутренним механизмам

## Подход

1. Прочитать код модулей `source`, `app`, `risk`, `analytics`, `platform` и тесты; для каждого механизма найти файл, функцию и тест, на который можно сослаться (путь и имя, без выдуманных).
2. Структура раздела «Как это устроено внутри»: схема (Mermaid) → путь события → таблица «механизм → файл → проверка → число» → «Что в Go сделано сознательно» → «Данные и нагрузка» → «Чего мы не утверждаем».
3. Числа — только из `docs/load/*.md`, `docs/model.md` и golden-файлов; перед вставкой сверить с файлом-источником. Если замер не делали, написать «не измерено».
4. Диаграммы Mermaid: потоки данных (источник → приём → БД → пересчёт → шина → чтение/SSE → клиент) и конвейер пересчёта (пачки → воркеры → сборка → публикация модели).
5. Оглавление и ссылки; проверка, что все относительные ссылки и якоря открываются; Mermaid валиден (отрисовывается на GitHub).
6. Тон: коротко, по фактам, для инженера-читателя; оговорки на месте, без рекламных слов.

# Дизайн: токен CSRF при восстановленной сессии

## Подход

1. `meOptions.queryFn`: после ответа 200 — `const t = response.headers.get('X-CSRF-Token'); if (t) setCsrfToken(t);`. Выход (`logout`) по-прежнему очищает токен. 401 токен не трогает.
2. Токен нужен до первого изменяющего запроса; `me` вызывается при загрузке оболочки (охрана маршрутов), то есть раньше любой кнопки записи. Исполнитель проверяет это по коду и записывает место вызова в `design.md`; если на какой-то странице запись возможна до ответа `me`, запрос ждёт его.
3. Сообщение 403: в `toApiError` для статуса 403 с телом про `X-CSRF-Token` — «Сессия устарела, обновите страницу». Остальные 403 (нет роли) — прежний текст.
4. Мок `me` в `mocks/handlers.ts` отдаёт заголовок `X-CSRF-Token`, как сервер.

## Допущения

- [ПРЕДПОЛОЖЕНО] Сервер отдаёт заголовок `X-CSRF-Token` в ответе `me` для любой cookie-сессии (по `http.go:222`); исполнитель подтверждает по коду и тесту сервера `auth`, а не по памяти.
- [ПРЕДПОЛОЖЕНО] Заголовок виден клиенту без дополнительной настройки: запросы идут на тот же адрес (прод и стенд за одним доменом), `Access-Control-Expose-Headers` не нужен.

## Риски

- Токен, взятый из `me`, относится к сессии cookie; при выходе в другой вкладке он станет недействительным — запись даст 403 с понятной фразой из п. 3, повторный вход чинит.

## Проверено по коду

- Сервер: `GetMe` ставит `X-CSRF-Token` из сессии (`backend/internal/auth/http.go:222`), проверка на записи — строки 128–129; тело 403 — `title: "Forbidden"`, `detail: "нужен заголовок X-CSRF-Token"` (`platform/httpx/problem.go:33–38`).
- Клиент: `ensureQueryData(meOptions)` вызывается в `beforeLoad` маршрутов `_app.tsx` и `index.tsx`, то есть до рендера любой страницы с кнопкой записи; ожидание в кнопках не нужно.
- [ПРОВЕРЕНО] допущение про заголовок: тот же origin, `Access-Control-Expose-Headers` не нужен.

## Решения по ходу

- Расхождение: в `proposal.md` фраза сервера названа текстом ошибки, но в `problem.title` лежит «Forbidden», а причина — в `detail`. Выбрано: распознаём 403 по `detail` с `X-CSRF-Token` (критерий кейса — понятное сообщение; контракт и сервер не трогаем).
- Заголовок `X-CSRF-Token` в `me` в `openapi.yaml` не описан — контракт не правился (по `proposal.md`); см. «Найдено по ходу».

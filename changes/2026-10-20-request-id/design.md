# Дизайн: X-Request-Id

## Подход

Библиотека `github.com/google/uuid`: разбор входящего значения (`uuid.Parse`) и генерация (`uuid.NewString`). Перед использованием API исполнитель сверяет сигнатуры по документации через Context7 (`resolve-library-id`, `query-docs`) и записывает в «Допущения» метку [ПРОВЕРЕНО] с названием и версией библиотеки.

Промежуточный слой `withRequestID(next http.Handler) http.Handler` оборачивает весь мукс. Для тестов и `main()` общая точка входа — `newHandler()`, которая возвращает `withRequestID(newMux())`; `newMux()` не меняется, существующие тесты остаются как есть.

## Отброшенные варианты

| Вариант | Почему нет |
|---|---|
| Свой генератор на `crypto/rand` | Лишний код для задачи, которую решает однострочный вызов библиотеки |
| Принимать любое значение из заголовка | Клиент мог бы подсунуть в идентификатор произвольную строку, которая потом попадёт в логи |

## Допущения

- [ПРЕДПОЛОЖЕНО] Допустим любой разбираемый `uuid.Parse` формат; в ответ возвращается нормализованная строка в нижнем регистре.

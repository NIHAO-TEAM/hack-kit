# Ядро модели: типы, настройки, окно списаний, шумовое ИЛИ, скор, уровни, деньги

## Зачем

Критерии жюри — «обоснованность модели» и «бизнес-польза»; требования кейса — score, уровни риска, денежная оценка, «Расширяемость: новые признаки… без существенной переработки» (`docs/case.md`). Это блокирующее изменение этапа 3 (`!risk-core`): признаки, действия и пересчёт строятся на его типах и реестре.

## Что меняется

- Пакет `internal/risk` — чистые функции без ввода-вывода и без `time.Now()`: `Score(snapshot, settings, asOf) → Result` по правилам `docs/model-rules.md`.
- Настройки модели с умолчаниями: веса признаков, пороги 70 / 50, горизонт 30 дней, `priceBasis` (`per_period` | `per_month`).
- Реестр признаков: признак — один файл с идентификатором, весом по умолчанию, функцией `f ∈ [0, 1]` и шаблоном причины; регистрируется сам, его вес появляется в настройках без правки других файлов.
- Два признака в этом изменении: `pwait` и `noauto` — чтобы проверить весь путь от признака до скора.
- Окно списаний, деньги услуги `R`, ожидаемая потеря, «под угрозой», «уже потеряно»; состояния клиента `scored` / `unscored` / `lost`.
- Причины по вкладу: у каждой услуги — список признаков с `f`, весом, вкладом и текстом причины.
- Уборка: удалить закоммиченный `tools/oracle/__pycache__/`, добавить `__pycache__/` в `.gitignore`.

Вне изменения:
- Признаки `funds`, `fail`, `susp`, `flight`, проверки качества данных и golden-тест на всех числах — `risk-features`.
- Действия с ценой и тег «к биллингу» — `money-actions`.
- Хранение настроек, загрузка снимка из базы, пересчёт по событиям — `recalc-engine`.
- HTTP — этап 4.

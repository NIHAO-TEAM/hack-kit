# Дизайн: кэш сессий

## Подход

1. `internal/auth/session_cache.go`: `type sessionCache struct{ shards [16]shard }`, шард выбирается по первому байту хэша токена; запись хранит `Identity` и момент истечения `min(now+TTL, expires_at)`.
2. Время — через `clock.Clock` (в тестах фейковые часы), не `time.Now()`.
3. `authenticate`: кэш → при промахе `singleflight.Group.Do(hash, …)` → БД → запись в кэш.
4. `logout` и удаление сессии: удаление из кэша до ответа.
5. `golang.org/x/sync/singleflight` — проверить, есть ли уже в `go.mod`; если нет, допустимо написать свой на 20 строк вместо новой зависимости.

## Допущения

- [ПРЕДПОЛОЖЕНО] Задержка отзыва сессии на других репликах до 5 с допустима для внутреннего сервиса; значение настраивается.

## Риски

- Смена роли пользователя администратором видна через TTL: роль в `Identity` кэшируется. Если смена роли есть в продукте — сбрасывать кэш по пользователю (проверить по коду).

## Решения по ходу

- Выключение кэша: `SESSION_CACHE_TTL=0` (или `Config.SessionCacheTTL == 0`) — кэша нет, каждый запрос ходит в БД. Пустое, неразобранное или отрицательное значение переменной — 5 с по умолчанию. Нулевая `Config{}` тоже без кэша, поэтому существующие тесты `apitest` проходят по-прежнему через БД, а кэш проверяют отдельные тесты `middleware_cache_test.go` и `session_cache_test.go`.
- `golang.org/x/sync/singleflight`: уже был в `go.mod` как косвенная зависимость v0.16.0, перенесён в прямые, новой зависимости нет. [ПРОВЕРЕНО] `singleflight.Group.Do`, golang.org/x/sync v0.16.0 (сигнатура `Do(key string, fn func() (any, error)) (v any, err error, shared bool)` проверена компиляцией). Context7 для этого не использовался.
- Запрос в БД на промахе идёт с `context.WithoutCancel`: он общий для всех ожидающих, отмена одного клиента не должна ронять остальных.
- Гонка выхода и загрузки: у кэша есть счётчик удалений (`gen`); загрузка, начатая до `delete`, не кладёт запись в кэш. Иначе выход во время промаха оставил бы сессию живой до TTL.
- Смена роли: роль меняется только при входе через SSO (`UpsertSSOUser`) и при старте (`ensureUsers`, кэш пуст). После SSO-входа записи всех сессий этого пользователя в реплике удаляются (`deleteUser`); в других репликах роль живёт не дольше TTL.
- Метрики: `AuthAPI.Collector()` подключён в `cmd/api/main.go` через `app.WithCollectors`. Тесты `apitest` сборщик не регистрируют.
- Нет Docker: PostgreSQL 16 поднят локально системным пакетом, тесты с БД и бенчмарки прогнаны.

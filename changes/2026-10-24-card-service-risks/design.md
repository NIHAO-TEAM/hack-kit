# Дизайн: оценки по услугам в карточке

## Подход

1. `CustomerPage` передаёт `detail.serviceRisks ?? []` в `ServiceList`; сопоставление по `serviceId`.
2. Панель услуги переиспользует отрисовку признаков и `formulaText` из `entities/customer-detail` (после `card-score-lost` он принимает вероятность 0..1).
3. Сверка: `Σ lossCents` по `serviceRisks` против `customer.expectedLossCents`; расхождение больше 1 цента — видимое предупреждение (не скрывать).
4. Моки: `serviceRisks` для клиента 9 из `testdata/golden` (не выдуманные числа).

## Отброшенные варианты

| Вариант | Почему нет |
|---|---|
| Отдельный эндпоинт по услуге | Данные уже в ответе карточки |

## Допущения

- [ПРОВЕРЕНО] `ServiceRisk` = `serviceId, probability (0..1), rCents, lossCents, features, quality` (`openapi.yaml:589`).
- [ПРЕДПОЛОЖЕНО] Ожидаемая потеря клиента = сумма `lossCents` его живых услуг — проверить по `risk/score.go`; если клиентская потеря считается иначе, сверку подписать так, как считается, и записать в «Найдено по ходу».

## Фронт

- Состояния: нет оценки у услуги (неживая) — пометка; пустой `serviceRisks` — старая подпись «оценок по услугам нет».
- Роль: маркетолог, аналитик, jury.

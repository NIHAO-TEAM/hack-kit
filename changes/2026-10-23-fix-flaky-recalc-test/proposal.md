# Стабильный тест пачки событий пересчёта

## Зачем

`TestBurstOfEventsMakesOneExtraRecalc` (`backend/internal/analytics/engine_test.go:84`, сценарий `specs/recalculation`) падает в CI на PR, которые не трогают движок: #69 (23578fc) и #63 (c56348c, run 40021100118). Каждое падение — лишний раунд CI и ревью, исполнители тратят время на «оспорено». Критерий: работоспособность (зелёный CI — условие слияния).

## Что меняется

- Тест детерминирован: проверяет то же требование («пачка событий во время расчёта — не больше одного дополнительного пересчёта»), но без `time.Sleep` и без расчёта на порядок горутин.
- Если тест нашёл настоящую гонку в движке (`internal/analytics/engine.go`) — исправление движка, а не теста.
- Прогон `go test -race -count=200 -run TestBurstOfEventsMakesOneExtraRecalc ./internal/analytics` зелёный.

Вне изменения:
- Ослабление проверки (например, «не больше 3 пересчётов») — нет: это ослабление гейта, нужно отдельное «да».
- Другие тесты движка — только если падают так же.

## Затронутые части

- backend: `internal/analytics` (тест, при гонке — движок)
- frontend: нет
- контракт `api/openapi.yaml`: нет
- защищённые пути: нет
- зависит от: нет

# Дизайн: модель чтения

## Подход

1. Прочитать `internal/app/portfolio.go` и обработчики списка клиентов; зафиксировать бенчмарком сегодняшнее время сортировки на 100k (до правки) и сохранить как базу.
2. Структура `ReadModel`: срез клиентов в порядке id, индексы позиций `byLoss`, `byScore`, `byEmail` (срезы `int32`), карта id → позиция; всё строится после пересчёта в фоне, публикуется `atomic.Pointer[ReadModel]`.
3. Список: фильтры (уровень, группа «у биллинга», поиск) применяются на индексе без копирования строк; страница — срез позиций; курсор — позиция в индексе плюс версия модели (при смене версии курсор отвергается с кодом `409`/понятной ошибкой, клиент начинает заново).
4. Память: индексы по 4 байта на клиента на сортировку; оценка для 100k — менее 10 МБ; записать в «Найдено по ходу» измеренную.
5. Совместимость: старые `page`/`limit` и порядок при равных значениях (вторичный ключ id) не меняются; существующие тесты `customers` проходят без правок.
6. Бенчмарки до и после; результаты в `docs/load/2026-10-24-read-model.md`.

## Допущения

- [ПРЕДПОЛОЖЕНО] Модель, построенная заранее, дешевле сортировки на запрос уже при 10k; выигрыш на 100k должен быть порядком величины (бенчмарком подтвердить).
- [ПРЕДПОЛОЖЕНО] Построение модели после пересчёта укладывается в долю секунды на 100k; если нет — строить параллельно по индексам.

## Риски

- Гонка публикации и чтения: читатель всегда видит либо старую, либо новую модель целиком; тест с `-race`.
- Курсор между версиями: явная ошибка вместо тихо неверной страницы.

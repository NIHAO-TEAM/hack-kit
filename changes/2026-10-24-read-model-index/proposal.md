# Модель чтения: очередь без блокировок и без БД

## Зачем

Эксперт aéza 24.10: интересен бэкенд и большие данные, использовать сильные стороны Go (ADR-0004). Замер стенда 23.10: `GET /customers` с сортировкой при 10 одновременных запросах — p95 1,78 с при цели 1 с на 100k клиентах. Чтение очереди — самый частый запрос. Результат пересчёта уже лежит в памяти (`Overview`), но сортировка и срез страницы идут на каждый запрос.

## Что меняется

- После каждого завершённого пересчёта строится неизменяемая модель чтения: клиенты один раз отсортированы по потере, скору, id и email (индексы — срезы позиций), есть быстрый поиск по id. Новая модель публикуется атомарно (`atomic.Pointer`), читатели берут указатель без блокировок и работают со снимком, который не меняется.
- `GET /customers`: сортировка, страница и фильтры берутся из индексов; для больших объёмов добавляется пагинация по курсору (`cursor`), совместимая со страницами `page`/`limit`, которые остаются.
- Данные в модели не пересекаются с записью: пересчёт строит новую, не трогая старую.
- Бенчмарки чтения `BenchmarkListByLoss100k`, `BenchmarkListByEmail100k`, число выделений на запрос.
- Нагрузочный сценарий k6 `docs/load/k6/read.js` уже есть; результат нового прогона записывается в `docs/load/2026-10-24-read-model.md` (если k6 недоступен, только бенчмарки и это указано).
- Результаты запросов (порядок, пагинация, фильтры) не меняются: тесты `customers` проходят без правок.

Вне изменения:
- Формулы модели.
- Хранение в БД: модель чтения живёт в памяти процесса и строится заново при старте и после каждого пересчёта.

## Затронутые части

- backend: `internal/app` (портфель), `internal/analytics` (чтение списка)
- frontend: нет (курсор необязателен)
- контракт `api/openapi.yaml`: да, необязательный параметр `cursor` и поле `nextCursor` в списке клиентов
- защищённые пути: `api/openapi.yaml` (необязательный курсор по причине выше)
- зависит от: `recalc-concurrency`

## Связанные решения

- ADR-0004; ADR-0001 (одна организация).
- Зависит от `recalc-concurrency` из-за общего `recalc.go`.

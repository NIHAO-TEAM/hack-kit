# Признак flight: вес 0 по умолчанию

## Зачем

Критерий «обоснованность модели». По кейсу (`docs/case.md:69`) `withdrawBalance` — заработанный на рефералах баланс, **доступный** к выводу. Факта вывода или движения денег в данных нет. `risk/feature_flight.go` считает `withdrawBalance / balance` с весом 0,15, а `docs/model.md:22` и экран «Модель» (`entities/model-config/model/features.ts:30`) описывают это как «Клиент выводит остаток». Вывод о поведении из данных не следует, а влияние заметное: сдвиг веса на 0,1 даёт ±187 € (`docs/model.md:77`).

Решение человека (сессия 24.10): вес `flight` по умолчанию 0, признак остаётся в реестре и может быть включён аналитиком.

**Меняет принятое правило модели** (`docs/model.md`, оракул `tools/oracle`, golden `testdata/golden`) и все контрольные числа демо. ADR-0001 признак не упоминает — ADR не меняется.

## Что меняется

- `flight.DefaultWeight()` = 0; оракул — тот же вес; golden перегенерирован оракулом.
- Признак называется честно: «Реферальный баланс к выводу» с пояснением «Доступно к выводу X из Y. Факт вывода в данных не виден; по умолчанию не влияет на риск».
- Все контрольные числа на данных организаторов пересчитаны оракулом и заменены в `docs/demo-script.md`, `docs/model.md` (таблица весов и чувствительности), `docs/model-rules.md`, `README.md`, `specs/*`, моках фронта, `e2e/tests/demo.spec.ts`.
- На проде сохранённые настройки модели, если в них явно записан `flight: 0.15`, сбрасываются к новым значениям по умолчанию (проверить, как хранятся).

Вне изменения:
- Прочие веса и признаки.
- Тексты «вероятность / эффект действия / О модели» — изменение `model-wording-honest`.
- Новый признак «реальный вывод» — данных нет.

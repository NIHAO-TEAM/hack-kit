# Проверка README краснеет: `PUT /source/snapshot` по токену не даёт 200

## Зачем

Первый запуск `Deploy README check` (изменение #170 `readme-quickstart-check`) на `main` `8f50f4b` красный: из всех проверок провалена одна — «PUT /api/v1/source/snapshot по токену» (`scripts/readme-quickstart.sh:124`), остальные (вход, сортировки, `/metrics`, `PATCH /model/settings`, перезапуск, выход) зелёные. Этой проверки хватает, чтобы жюри не смогло повторить README как написано. Тело ответа в логе не печатается, поэтому причина не видна.

Причина (гипотеза): тело снимка в скрипте не проходит текущую проверку (`validate.go`): например, связи, обязательные поля или ограничения после новых правил (`сумма в 0..1000`), либо `SOURCE_TOKEN` в `.env` раннера пуст (в `.env.example` он пустой) и токен не принимается. Проверить запросом и ответом, не гадать.

## Что меняется

- Скрипт при падении проверки печатает код и тело ответа (без токенов и паролей), чтобы причина была видна в логе.
- Находится настоящая причина (тело снимка, пустой `SOURCE_TOKEN` в `.env` быстрого запуска, порядок шагов) и исправляется там, где ошибка: в скрипте, если неверен пример; в README и `.env.example`, если инструкция не говорит, что `SOURCE_TOKEN` надо задать; в сервере, если он отвергает корректный снимок.
- Скрипт и README после правки совпадают буквально; проверка остаётся строгой (ожидаемый код 200 не меняется на «любой»).

Вне изменения:
- Остальные проверки скрипта.
- Рабочий процесс `.github/workflows/deploy-readme-check.yml` (его правит человек).

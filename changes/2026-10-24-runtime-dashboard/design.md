# Дизайн: дашборд «Внутри сервиса»

## Подход

1. Сначала список метрик, которые реально отдаёт `/metrics` на `main` (поднять сервер локально, `curl /metrics`); в «Найдено по ходу» — что есть, чего нет.
2. Дашборд — JSON рядом с `churn.json`, подхватывается тем же provisioning; uid постоянный.
3. HTTP-гистограмма: `churn_http_request_duration_seconds{route,method,code}`, `route` — шаблон из маршрутизатора; бакеты 5 мс…5 с.
4. Проверка: тест, что JSON дашборда разбирается и каждый запрос PromQL ссылается на метрику из списка, который отдаёт сервер в тесте (или помечен «нет данных до слияния»).
5. Скриншот дашборда во время `Deploy load` — в `docs/load/` (если владелец запустит замер).

## Допущения

- [ПРЕДПОЛОЖЕНО] Удаление панелей задач из Grafana следует из ADR-0004 п. 1 («интерфейса нет»); метрики задач на сервере остаются.

## Риски

- Кардинальность меток HTTP: только шаблон маршрута, без id и query.

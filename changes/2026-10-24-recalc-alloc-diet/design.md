# Дизайн: пересчёт без лишних выделений

## Подход

1. `go test -bench Recalc100k -benchmem -memprofile` на `main`; топ-10 мест выделений в «Найдено по ходу».
2. Править только места из топа, по одному, с `benchstat` после каждого; правка без выигрыша откатывается.
3. Типичные приёмы: `scratch` на воркер (`[]float64` вкладов, `[]string` id признаков) с `s = s[:0]`; `strings.Builder` из пула для причин; отказ от `fmt.Sprintf` в горячем пути (причины форматировать, когда их читают).
4. Равенство результатов: golden, `-tags parity` на 10k, тест равенства конвейера и последовательного расчёта (#146).

## Допущения

- [ПРЕДПОЛОЖЕНО] Ленивая строка причины допустима, если API отдаёт тот же текст; иначе причины форматируются как сейчас.

## Риски

- Гонки на общих буферах: буферы строго на воркер; `-race`.

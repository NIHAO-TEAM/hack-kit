# Дымовая проверка прода после каждого выката

## Зачем

Шкала «Архитектура» 6 и «Работоспособность» 3–6: жюри открывает прод, а не локальный стенд. Сейчас после выката проверяется только `/healthz` (`deploy.yml`), а `e2e/tests/demo.spec.ts` нигде не запускается автоматически (в `.github/workflows/` его нет) и на проде с `SEED_STAND=true` упадёт на суммах шага 1 (`e2e/README.md`).

## Что меняется

- `e2e/tests/smoke.spec.ts` (Firefox, без привязки к суммам данных): главная открывается, Swagger на `/api/v1/docs`, без входа — 401 на путях с данными, `/metrics` без токена закрыт, Grafana за входом; при заданном пароле `jury` — вход, очередь не пустая, карточка первого клиента открывается, сводка = сумме очереди.
- Новый workflow `.github/workflows/deploy-smoke.yml`: после успешного `deploy.yml` или `deploy-k8s.yml` и вручную; итог — в сводке запуска; падение — красный запуск и одна issue с меткой `prod-down`.
- Часть со входом запускается, только если есть секрет `E2E_JURY_PASSWORD`; без него — только открытые проверки.

Вне изменения:
- Полный демо-сценарий на проде (меняет данные прода) — нет.
- Существующие workflow и гейты не меняются.

## Затронутые части

- backend: нет
- frontend: нет
- контракт `api/openapi.yaml`: нет
- защищённые пути: да — `e2e/` (новый тест), `.github/workflows/deploy-smoke.yml` (новый; `executor.md` разрешает новые `deploy*.yml`)
- зависит от: нет

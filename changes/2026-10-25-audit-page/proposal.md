# Журнал — отдельная страница

## Зачем

Эксперт aéza 25.10 10:28: «журнал почему-то прямо на страничке модели расположен». Проверено по коду: виджет `AuditLog` стоит внизу `pages/model-settings/ui/ModelPage.tsx` и `pages/source/ui/SourcePage.tsx`; в нём входы и выходы всех пользователей, к настройкам модели не относятся. Шкала: «UX», «Архитектура интерфейса».

## Что меняется

- Новый пункт меню «Журнал» (`/audit`) — для ролей, которым сервер отдаёт журнал (аналитик, администратор, `jury`); маркетолог пункта не видит.
- Страница «Журнал»: тот же виджет `AuditLog` (пагинация, подписи), заголовок h1 «Журнал».
- С «Модели» и «Источника» журнал убирается.

Вне изменения:
- API журнала (`GET /api/v1/audit`) и его права не меняются.
- Фильтры журнала по типу и автору — не делаем (стоп-кодинг 14:00).

## Затронутые части

- backend: нет
- frontend: `app/routes` (новый маршрут `_app.audit`), `app/layout/AppShell` (пункт меню), `entities/session` (право показа, если нужно), `pages/model-settings`, `pages/source`, новая `pages/audit`
- контракт `api/openapi.yaml`: нет
- защищённые пути: нет
- зависит от: нет

## Связанные решения

- ADR-0001: роли и права проверяются на сервере; меню лишь прячет пункт.
- Макет: нет, страница из существующего виджета [ПРЕДПОЛОЖЕНО — фриз, этап 9].

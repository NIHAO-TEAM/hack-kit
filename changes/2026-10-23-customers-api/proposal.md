# `GET /customers` и `GET /customers/{id}`: рейтинг, сортировки, карточка клиента

## Зачем

Кейс: «Топ клиентов под риском. Таблица содержит ID, email, баланс, общую сумму пополнений и isk-score. Обязательна сортировка по ID, email, балансу и общей сумме пополнений в обе стороны»; «Подробная оценка клиента, его услуг, признаков риска и объяснений»; «При недостатке данных… явно указать отсутствие оценки» (`docs/case.md`). Защита, шаги 1–2.

## Что меняется

- `GET /api/v1/customers` — строки из последнего пересчёта (схема `CustomerRow`): ID, email, баланс, пополнено, скор, уровень или состояние (`unscored`, `lost`), ожидаемая потеря, главная причина, главное действие с эффектом, данные окна спасения (`expiresAt`, дата удаления), тег «к биллингу».
- Фильтр `level`, поиск `q` по email; сортировка `sort=id|email|balance|totalReplenished|score|expectedLoss`, `order=asc|desc`; по умолчанию — ожидаемая потеря по убыванию; «нет оценки» и «потерян» всегда внизу, внутри — по ID; `limit` (1..200), `offset`, ответ `{items, total}`.
- `GET /api/v1/customers/{id}` — услуги с вероятностью, `R`, потерей, признаками (значение, вес, вклад, текст причины) и проверками качества; деньги клиента; действия с ценой; неизвестный ID — `404`.
- Ответы несут `version` пересчёта.

Вне изменения:
- Сводка и метрики — `summary-metrics`; SSE — `live-updates`; экраны — `queue-screen`, `customer-card-screen`.

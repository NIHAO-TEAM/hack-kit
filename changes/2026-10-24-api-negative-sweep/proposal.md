# Ни одного 500 на кривой ввод: проход по всем операциям контракта

## Зачем

«Ничего не падает» (владелец со слов эксперта, 24.10; ADR-0004, п. 6). Жюри и эксперт будут тыкать API руками через Swagger: пустые тела, строки вместо чисел, отрицательные `limit`, несуществующие id, огромные значения, лишние поля. Ответ `500` на кривой ввод выглядит как падение. Есть отдельные тесты ошибок, но нет прохода по всем операциям контракта сразу.

## Что меняется

- Тест `internal/apitest`: по `api/openapi.yaml` перечисляются все операции; для каждой — набор кривых запросов, построенных из схемы (неверный тип, вне диапазона, пустое и битое тело, лишнее поле, несуществующий id, слишком длинная строка, тело больше предела); под ролью `jury` и без сессии.
- Ожидание: ни одного `5xx`; ответы `4xx` в `application/problem+json` с `correlation_id` (как требует `backend/AGENTS.md`); коды из контракта.
- Найденные `500` чинятся в том же изменении, если правка локальна (проверка ввода в обработчике); крупное — запись в «Найдено по ходу» и черновик.
- Fuzz-цель `FuzzAPI` поверх того же генератора (короткий прогон в CI, длинный — локально), если укладывается во время CI.

Вне изменения:
- Контракт (коды берутся из него; если код ответа в контракте не описан — запись в «Найдено по ходу», правка контракта отдельно).

## Затронутые части

- backend: `internal/apitest` (тест), точечные проверки ввода в обработчиках модулей
- frontend: нет
- контракт `api/openapi.yaml`: нет
- защищённые пути: нет
- зависит от: нет

## Связанные решения

- `backend/AGENTS.md`: ошибки — `problem+json`.
- Гейт не ослабляется: новый тест добавляет проверку.

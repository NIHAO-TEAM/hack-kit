# Очередь по причине: клик по «где теряем деньги» показывает этих клиентов

## Зачем

ADR-0004, п. 5: глубже в кейс. На «Сводке» есть блок «Где теряем деньги» по причинам (#142), но, по его proposal, клик по причине без фильтра очереди «только блок». Маркетологу нужен следующий шаг: «приостановленные услуги — 1 844 €» → список этих клиентов с действием. Это прямо отвечает на «кому нужно внимание и почему» и даёт кампанию по одной причине.

## Что меняется

- `GET /customers?reason=<признак>`: клиенты, у которых признак есть среди причин с ненулевым вкладом; сортировка по потере по этой причине (`lossByFeature` клиента), остальные сортировки и страницы как сейчас.
- Фильтр работает через модель чтения (#147): индекс «признак → клиенты» строится вместе с моделью.
- Очередь: фильтр «Причина» рядом с уровнем риска; на «Сводке» клик по полосе причины открывает очередь с фильтром; в строке очереди — потеря по этой причине.
- CSV учитывает фильтр.

Вне изменения:
- Модель и признаки.

## Затронутые части

- backend: `internal/analytics` (фильтр, индекс в модели чтения)
- frontend: «Очередь», «Сводка»
- контракт `api/openapi.yaml`: да, необязательный параметр `reason` (добавление)
- защищённые пути: `api/openapi.yaml` (по причине выше)
- зависит от: `read-model-index`

## Связанные решения

- ADR-0004, п. 5; ADR-0001.
- Зависимость — модель чтения и общий `openapi.yaml`.

# Пересчёт: настройки модели в базе, чтение снимка, один воркер с версиями

## Зачем

Кейс: «После изменения данных или коэффициентов score, рейтинг и денежные показатели обновляются автоматически»; «Настройки сохраняются после перезапуска приложения» (`docs/case.md`, требования 3 и 5). Дебаты: гонки PATCH/snapshot закрываются одним воркером и парой версий (`docs/decision/03_verdict.md`, правка 10; `r1_B.md` №8).

## Что меняется

- Настройки модели хранятся в базе (`model_settings`), при пустой таблице — умолчания из `risk.Defaults()`; у настроек есть номер версии. Изменение настроек публикует событие `model.changed`.
- Снимок читается из таблиц организаторов вместе с `asOf` и версией снимка.
- Один воркер пересчёта в `analytics`: по событиям `source.changed` и `model.changed` (и при старте) читает снимок и настройки, вызывает `risk.Score`, держит последний результат в памяти. Пачка событий подряд даёт один пересчёт («грязный» флаг), а не очередь.
- Результат помечен парой версий (`dataVersion`, `settingsVersion`) и общей монотонной `version`; после пересчёта публикуется `recalculated` с `version`.
- Время пересчёта и возраст снимка доступны для метрик (их выводит `summary-metrics` на этапе 4).

Вне изменения:
- HTTP: `GET/PATCH /model/settings`, `/customers`, `/summary`, `/metrics`, SSE `/events` — этап 4.
- Предпросмотр `dryRun` — `settings-api` (этап 4) вызывает `risk.Score` напрямую с черновыми настройками.

## Затронутые части

- backend: `internal/model` (новый `store.go`), `internal/source` (новый `reader.go`), `internal/analytics` (новый `engine.go`); подключение воркера в `internal/app/app.go` — одна строка
- frontend: нет
- контракт `api/openapi.yaml`: нет
- защищённые пути: нет

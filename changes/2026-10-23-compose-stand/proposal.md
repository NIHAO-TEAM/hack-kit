# Запуск одной командой: Dockerfile, Docker Compose, `.env.example`, README продукта

## Зачем

Кейс: «Решение описано и запускается через Docker Compose»; приёмка: «Жюри запускает приложение по README»; «Передача решения: исходный код, Compose-файл, инструкция запуска» (`docs/case.md`). Это слой 1 (`docs/decision/03_verdict.md`, правка 2) и основа прода на этапе 5.

## Что меняется

- `Dockerfile` в корне: многоступенчатая сборка — фронт (`pnpm build`, если в `frontend/package.json` есть скрипт `build`), затем Go-бинарь со встроенным фронтом; итоговый образ distroless, не от root.
- `internal/platform/webui` раздаёт собранный фронт на `/` с откатом на `index.html` для маршрутов SPA; без сборки — страница «фронт не собран».
- `docker-compose.yml` в корне: `postgres` (без опубликованного порта, том, healthcheck) и `app` (ждёт базу, миграции при старте, сид организаторов, порт `8080`).
- `.env.example` — все переменные с пустыми паролями и токенами и комментарием, как их задать; `.env` в `.gitignore`.
- Корневой `README.md` становится README продукта: что это, запуск (`cp .env.example .env`, задать пароли, `docker compose up -d`), проверка (`/healthz`, вход, `/api/v1/docs`), где модель и архитектура (ссылки, заполняются позже), раздел «Дополнительно» (пустой список). Текущий README кита переезжает в `hack-kit/`.

Вне изменения:
- Прод, TLS, Caddy — этап 5 (`prod-compose`); Helm и k3s — этап 6.
- Prometheus и Grafana в Compose — этапы 6–7.
- Проверка «Compose на чистой машине» в CI — правка `.github/`, её делает человек или пахан по «да» («Найдено по ходу»).

## Затронутые части

- backend: `internal/platform/webui` (заполняет заглушку из `churn-foundation`)
- frontend: нет (только вызов `pnpm build` из Dockerfile)
- контракт `api/openapi.yaml`: нет
- защищённые пути: нет

# Экраны на 100k: прерванная переходом загрузка шрифта не считается ошибкой экрана

## Зачем

`Deploy UI 100k` на `main` bdf56d0 упал один раз (прогон 40156747075, 03:05 UTC) и прошёл на следующем запуске того же коммита. Все цели времени достигнуты (очередь 744 мс, CSV 100 000 строк), упала только проверка «ошибки консоли» в Firefox:

`/queue/9: downloadable font: download failed (font-family: "Inter" ...): status=2152398850 source: .../assets/inter-cyrillic-400-normal-*.woff2`

`2152398850` = `0x804B0002` = `NS_BINDING_ABORTED`: Firefox отменил загрузку шрифта, потому что тест уже перешёл на следующий экран. Шрифт на месте, экран не сломан. Это то же самое, что штатный обрыв SSE при переходе, который тест уже исключает (`sseClosed`, `e2e/tests/ui-100k.spec.ts:79`). Проверка, которая падает от случайного тайминга, перед защитой мешает: красный прогон после выката выглядит как поломка.

## Что меняется

- `e2e/tests/ui-100k.spec.ts`: исключить из «ошибок консоли» только сообщение Firefox о загрузке шрифта со статусом `2152398850` (`NS_BINDING_ABORTED`), с комментарием, как у `sseClosed`. Любая другая ошибка шрифта (404, неверный формат, другой статус) по-прежнему ошибка.
- Проверить, нет ли такого же фильтра нужды в других спецификациях с `page.on('console')` (сейчас только эта).

Вне изменения:
- Порог «0 ошибок консоли» не ослабляется для остальных сообщений.
- `.github/workflows/` не трогаем.

# Дизайн-система

Направление уже выбрано в ADR-0002 и здесь не пересматривается. Этот скилл — как воплощать его в коде одинаково на всех экранах. Заполняется в день 0 значениями из ADR-0002; структура и правила остаются.

Проверка: витрина `/dev/ui` в `pnpm dev` (все токены и компоненты, переключатель темы) и `pnpm check`.

## Цвет

Цвет сообщает смысл, а не украшает.

- **Нормальное состояние — без цвета.** Свежая партия, обычная строка, неактивный пункт.
- **Внимание** (`warn`) — нужно решение скоро.
- **Опасность или запрет** (`critical`) — просрочено, стоп-лист, необратимое действие.
- **Фирменный цвет** (`primary`) — основное действие, активный пункт навигации, успех. **Одна кнопка с заливкой на экран.**
- **Статус всегда дублирован текстом или иконкой с подписью.** Цвет не единственный носитель смысла.

### Устройство токенов

Имена — по роли, не по оттенку (`--gray-700` запрещено). Для каждого тона статуса четыре токена, как у SwapOwl и Goden:

| Токен | Где |
|---|---|
| `--<tone>-fg` | текст и иконка статуса на обычном фоне |
| `--<tone>-tint` / `--<tone>-on-tint` | фон плашки / текст на ней |
| `--<tone>-solid` | заливка счётчика и графика |
| `--<tone>-row` | фон строки таблицы (только `warn`, `critical`) |

Тона: `ok`, `warn`, `risk` (если в предметной области есть третья ступень), `critical`, `neutral`, `info`. Плюс поверхность: `--bg`, `--surface`, `--surface-sunken`, `--surface-hover`, `--border`, `--border-strong`, `--field-border` (≥ 3 : 1), `--text-strong`, `--text`, `--text-muted`, `--text-subtle`, `--focus-ring`, `--overlay`, `--row-changed`.

Значения обеих тем — только в `tokens.ts`. В компонентах:

```tsx
<Text c="var(--text-muted)" />
<Badge bg="var(--warn-tint)" c="var(--warn-on-tint)" />
```

Hex, `rgb()` и именованные цвета в компонентах запрещены (Stylelint: `color-no-hex` в `*.module.css`, ESLint: правило на литералы цвета в `style`/`sx`).

### Автотест контраста

Каждая пара «текст на фоне» записана в `contrastPairs`. Тест проверяет обе темы: обычный текст ≥ 4,5 : 1, крупный (≥ 24 px или ≥ 19 px полужирный) и графика ≥ 3 : 1. Новый цвет — сначала в `tokens.ts` для обеих тем и в `contrastPairs`, тест не даст опуститься ниже AA.

```ts
// contrast.ts
const lum = (hex: string) => {
  const [r, g, b] = [1, 3, 5].map((i) => {
    const c = parseInt(hex.slice(i, i + 2), 16) / 255;
    return c <= 0.03928 ? c / 12.92 : ((c + 0.055) / 1.055) ** 2.4;
  });
  return 0.2126 * r + 0.7152 * g + 0.0722 * b;
};
export const ratio = (a: string, b: string) => {
  const [hi, lo] = [lum(a), lum(b)].sort((x, y) => y - x);
  return (hi + 0.05) / (lo + 0.05);
};
export const contrastPairs = [
  { fg: 'text', bg: 'surface', min: 4.5 },
  { fg: 'text-muted', bg: 'surface', min: 4.5 },
  { fg: 'warn-on-tint', bg: 'warn-tint', min: 4.5 },
  { fg: 'field-border', bg: 'surface', min: 3 },
  // …каждая пара, которая встречается в интерфейсе
] as const;
```

```ts
// contrast.test.ts
describe.each(['light', 'dark'] as const)('контраст, тема %s', (mode) => {
  it.each(contrastPairs)('$fg на $bg не ниже $min', ({ fg, bg, min }) => {
    expect(ratio(colorTokens[mode][fg], colorTokens[mode][bg])).toBeGreaterThanOrEqual(min);
  });
});
```

## Типографика

- Один шрифт интерфейса (из ADR-0002), 2–3 насыщенности. Второй шрифт — только если он и есть сигнатура (у SwapOwl — моно в заголовках и рукописные пометки), и только в оговорённых местах.
- **Табличные цифры глобально** (`font-variant-numeric: tabular-nums`): колонки чисел ровные.
- Варианты ограничены: `h1` — заголовок страницы (один, его даёт `PageHeader`), `h2` — заголовок диалога, `h3` — секция, `body`, `body-strong`, `small`, `caption`, `num`. Остальные заголовки (`h4`–`h6`) не используются.
- Иерархию дают размер, насыщенность и цвет. Не надписи капсом с разрядкой над каждой секцией, не цветные «плашки-заголовки».
- Числа по-русски: десятичная запятая, неразрывный пробел перед единицей, минус U+2212.

## Отступы, радиусы, глубина

- Шаг 4 px. Значения: 4, 8, 12, 16, 20, 24, 32, 48. Другие числа в отступах запрещены.
- Радиусы — по типу элемента: плашка 4, контрол 6, карточка 10–12, диалог 14. Одно значение на тип во всём продукте.
- **Глубина одним способом.** В потоке страницы — тонкая рамка `--border`, без теней. Тени — только у всплывающих слоёв: меню, тост, диалог, drawer.

## Плотность

- Размер — по способу ввода: `@media (pointer: coarse)` → цели касания от 44 × 44, основная кнопка 48. На ноутбуке контролы 32–40.
- Раскладка — по ширине: от 1200 px боковая панель, уже — рельс из иконок; меньше 768 — нижняя навигация для ролей, у которых главный экран на телефоне.
- Таблица на узком экране прокручивается внутри карточки, страница горизонтально не прокручивается. На планшете списки становятся карточками (`CardList`).

## Иконки

- Один набор через `<Icon name="…" />`. Новая иконка — одна запись в реестре. Прямые импорты SVG в компонентах запрещены.
- Без `label` иконка декоративная (`aria-hidden`), с `label` — озвучивается. Кнопке из одной иконки нужен `aria-label`.
- Иконка не заменяет подпись у действия, которое встречается редко.

## Каталог `shared/ui`

Перед новым компонентом проверь этот список. Компонент без бизнес-логики, с публичным API через `index.ts`, на витрине `/dev/ui` во всех состояниях.

| Компонент | Когда |
|---|---|
| `AppShell` | оболочка: навигация по правам, переключатель точки, время стенда, индикатор связи |
| `PageContent` | содержимое страницы со стандартными отступами; слот `actionBar` |
| `PageHeader` | путь, `h1`, статус, подробности, действия — на каждой странице |
| `SectionTabs` | вкладки раздела, на планшете во всю ширину |
| `ActionBar` | итог и основное действие внизу формы или выбора |
| `StatusBadge` | статус по шкале: иконка + метка + тон, высота 22 |
| `StatusCounter` | счётчик «N истекают» с тоном, по клику — список |
| `QueryState` | обёртка запроса: скелетон, ошибка с «Повторить», данные |
| `EmptyState` | пусто: иконка, заголовок, одна фраза, действие (приглашение, не извинение) |
| `NoResultsState` | фильтр ничего не нашёл: что искали и «Сбросить» |
| `ErrorState` | не удалось загрузить: причина по-человечески, `request_id`, «Повторить» |
| `ConnectionBanner` | нет связи: плашка над контентом, данные остаются, метка «могли устареть · HH:MM» |
| `ForbiddenState` | нет прав: какая роль нужна, куда вернуться |
| `DataTable` | таблица: сортировка сервера, `aria-sort`, раскрытие строки, подсветка изменившейся строки |
| `CardList` | список карточек вместо таблицы на планшете и телефоне |
| `QuantityField` | ввод количества: −/+, десятичная запятая, единица в подписи |
| `ConfirmDialog` | любое необратимое действие |
| `FormDialog` | форма в диалоге: Enter отправляет, состояние отправки |
| `RetryAlert` | неудачная запись: ошибка, пояснение, «Повторить» |
| `RoleGate` | показать детей, только если у профиля есть право на точке |
| `RelativeTime` | «через 14 ч» от времени стенда, точная дата в подсказке |
| `Money`, `Quantity` | деньги и количество через `format.ts` |
| `EmptyValue` | прочерк «—» на месте пустого значения |
| `Icon`, `Logo` | иконка из реестра; знак продукта для обеих тем |

Остальное — компоненты Mantine как есть: тема уже приводит их к системе. `Button`: `filled` — основное действие (одно на экран), `default`/`outline` — вторичное, `subtle` — тихое, `color="critical"` — необратимое. `TextInput`: подпись всегда над полем.

## Куда писать стиль

1. Подходит компонент Mantine или `shared/ui` как есть — используй без стилей.
2. Разовая раскладка (отступы, flex, grid) — пропсы Mantine (`gap`, `p`) или `*.module.css` с токенами.
3. Повторяется во втором месте — компонент в `shared/ui` (без бизнес-логики) или в слой своей фичи.
4. Нужно изменить вид компонента Mantine везде — `components.ts`, а не точечные стили.

## Тема

По умолчанию — системная, неизвестна — светлая. Явный выбор сохраняется и важнее системной. Скрипт ранней установки ставит тему до загрузки приложения, без мигания. Тёмная тема — полноценная, проверяй в ней каждый экран: не инвертированная светлая, а свои значения поверхностей и тонов.

## Витрина `/dev/ui`

Один маршрут, всё на одной прокрутке: палитра обеих тем с подписями смысла, типографика, отступы и радиусы, каждый компонент `shared/ui` во всех состояниях, шкала статусов целиком. Новая запись в каталоге — новая секция витрины в том же PR. Витрина — то, что видят глаза ревьюера: косметику проверяет она, а не unit-тесты.

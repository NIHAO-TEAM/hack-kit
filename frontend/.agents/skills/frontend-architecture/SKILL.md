# Архитектура фронтенда

Облегчённый Feature-Sliced Design. Слои проверяет `pnpm lint:fsd` (steiger). Нарушение исправляется переносом кода, а не исключением в конфиге.

## Слои

| Слой | Что лежит | Пример |
|---|---|---|
| `app` | провайдеры, роутер, файлы маршрутов, оболочка, realtime, тема | `app/routes/points.$pointId.stock.tsx` |
| `pages` | страница маршрута: собирает виджеты и фичи, своего состояния почти нет | `pages/stock` |
| `widgets` | крупный самостоятельный блок страницы | `widgets/stock-table` |
| `features` | действие пользователя с формой или мутацией | `features/accept-delivery` |
| `entities` | сущность: типы из схемы, ключи и options запросов, форматтеры, мелкий UI | `entities/batch` |
| `shared` | без предметной области: `api`, `ui`, `lib`, `config` | `shared/ui/status` |

- Импорт только в нижний слой. Слайсы одного слоя друг друга не импортируют: общее уходит вниз.
- У слайса публичный `index.ts`. Импорт мимо него запрещён.
- Внутри слайса сегменты: `ui/`, `model/` (чистые функции, состояние), `api/` (ключи, options, мутации), `lib/`.
- Не плоди `entities`: сущность заводится, когда её используют хотя бы две фичи или страницы.
- Алиасы по слоям: `@app/*`, `@pages/*`, `@widgets/*`, `@features/*`, `@entities/*`, `@shared/*`. Общего `@/` нет.

## Маршруты

- Файлы маршрутов — `src/app/routes/`, дерево `routeTree.gen.ts` генерирует плагин, оно коммитится и руками не правится.
- Разделы живут на точке: `/points/$pointId/<раздел>`. Layout точки проверяет её в загрузчике и кладёт в контекст маршрута.
- Право раздела проверяется в `beforeLoad` маршрута (`requireRight('stock.view')`): нет права — экран «Недостаточно прав», а не пустая страница.
- Ссылки — типизированные компоненты-обёртки (`ButtonLink`, `TextLink`), чтобы путь и параметры проверялись.
- Загрузчик маршрута начинает запросы заранее (`ensureQueryData`), страница читает через `useSuspenseQuery` или `useQuery`.

## Данные

- Клиент API — `shared/api`: базовый адрес, токен, `ApiError` с готовым `message`, `fieldErrors`, `requestId`. Ошибки — по RFC 9457 (`application/problem+json`).
- Типы — только из `schema.gen.ts` (`pnpm api:types`). Руками типы ответов не пишутся. CI падает, если генерация даёт дифф.
- Ключи запросов — от префикса точки: `[...pointKey(pointId), 'stock', params]`. Так весь раздел точки сбрасывается одним ключом, и сигнал SSE сбрасывает категорию.
- Ключи и `queryOptions` живут в `entities/<сущность>/api`, а не в компонентах.
- Мутация после успеха сбрасывает ключи своей категории; оптимистичное обновление — только если откат прост и показан человеку.

## Права

- Профиль `GET /me` загружается до создания роутера и лежит в кэше Query: точки, роль на каждой, права.
- `can(point, 'deliveries.accept')` — единственный способ проверить право. Роль в коде не сравнивается строкой (`role === 'manager'` запрещено): права роли определяет сервер.
- `RoleGate` скрывает действие без права. Сервер проверяет всё заново.

## Реальное время

- `app/realtime`: один поток SSE открытой точки, состояние связи — в оболочку.
- Сигнал содержит категории, не данные. Обработчик сбрасывает ключи этих категорий.
- В тестах поток подменяется `FakeEventSource`.

## Моки

- `src/mocks/`: обработчики MSW по тем же типам схемы, состояние в памяти, демо-данные совпадают с сидом бэкенда.
- `pnpm dev:mock` — фронт без бэкенда. Новая операция API — обработчик мока в том же PR.
- Моки не попадают в продакшен-сборку.

## Сгенерированное

`schema.gen.ts`, `routeTree.gen.ts` и подобные — коммитятся, не правятся руками, исключены из линтеров.

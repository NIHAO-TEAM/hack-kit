# Тесты фронтенда

## Нужен ли тест

Тест нужен для значимого сценария, достижимого крайнего случая и реальной регрессии. Процент покрытия и число тестов — не цель. Перед тестом ответь:

- Какое реальное поведение или сбой он ловит?
- Не покрывает ли это уже другой тест, в том числе ниже уровнем?
- На каком самом низком уровне это проверяется достоверно?

Нет отдельной пользы — не пиши, прогони существующие.

## Что проверять

- Наблюдаемый результат и инварианты нашего кода. Не переписывай реализацию в проверки.
- Крайний случай — только достижимый при текущем контракте.
- **Не тестируй косметику** (цвета, классы, отступы): её проверяют витрина `/dev/ui`, скриншоты и глаза. Исключения — автотест контраста и геометрия, от которой зависит работа (видимость, перекрытие) — её в Playwright.
- Не тестируй гарантии библиотек (React, Mantine, TanStack, браузер).
- Права: экран под ролью без права показывает «Недостаточно прав», действие скрыто — по одному тесту на раздел.

## Уровни

| Уровень | Чем | Что |
|---|---|---|
| Чистая функция | Vitest | `format.ts`, `model/*`, шкала статусов, `contrast` |
| Компонент | Testing Library + `renderWithTheme` | поведение компонента `shared/ui` и фичи |
| Приложение | `renderApp(path, { profile })` + `mockGet` | маршрут, права, загрузка, пять состояний |
| Браузер | Playwright, **Firefox** | e2e демо-сценария на стенде, скриншоты, геометрия |

Тест лежит рядом с модулем: `foo.tsx` → `foo.test.tsx`. Тексты `describe` и `it` — по-русски и про поведение: «Escape закрывает диалог без действия», а не «вызывает onClose».

## Поиск элементов

- Как пользователь: `getByRole(роль, { name })`, поле — `getByLabelText`. Заодно проверяет, что у элемента есть роль и подпись.
- `data-testid` — только где роли и подписи нет и быть не должно (контейнер прокрутки).
- Не выбирай по номеру в списке (`getAllByRole(...)[1]`).
- Нет подписи у контрола — добавь `aria-label`, а не testid.

## Хелперы (`@shared/lib/test-utils`, `src/app/test-*.ts`)

| Что | Хелпер |
|---|---|
| Рендер в теме | `renderWithTheme(ui, { mode? })` |
| Приложение на адресе с профилем | `renderApp(path, { profile?, wide? })` |
| Профиль и роли | `testProfile()`, `testStaffPoint(role)`, готовые `manager`, `cook`, `waiter` |
| Ответы API | `mockGet((url, params) => …)`, готовые ответы разделов |
| Запросы и параметры | `requestsTo(mock, '/stock')`, `lastParams`, `idempotencyKeyOf(call)` |
| Поток SSE | `FakeEventSource`, `connect()`, `signal(categories)` |
| Ширина и способ ввода | `mockMatchMedia`, `mockWideScreen()`, `mockCoarsePointer()` |
| Системная тема | `mockSystemColorScheme('dark')` |

`vitest.setup.ts` после каждого теста возвращает таймеры, размонтирует, чистит `localStorage`; `mockReset: true` сбрасывает моки перед каждым тестом. Общие ответы — в `beforeEach`, не на уровне модуля.

## Подводные камни

- **jsdom без раскладки:** размеры нулевые, `scrollTo` не реализован. Геометрию и прокрутку — в Playwright.
- **Неактивная кнопка с `pointer-events: none`:** `userEvent.click` бросает ошибку. Проверка «нажатие ничего не делает» — `userEvent.setup({ pointerEventsCheck: 0 })`.
- **Клиент Query в тестах** без повторов после ошибки: тест на «Повторить» нажимает кнопку сам.
- **Время** — фейковые таймеры и время стенда из мока `/api/clock`, а не `Date.now()`.
- **Playwright:** только Firefox (Chromium в нашей среде запрещён). Стенд перед e2e сбрасывается штатной командой.

## Прогоны

```bash
pnpm exec vitest run <путь>   # тесты изменения
pnpm typecheck                # vitest типы не проверяет
pnpm lint:fsd                 # если менялись импорты между слайсами
pnpm check                    # перед PR — всё
```

# Визуальная проверка

Успех нельзя утверждать по исходному коду. Проверяется отрисованный экран.

## 1. Скриншоты

`pnpm shots -- --routes <маршруты изменения>` (`scripts/screenshots.mjs`, Playwright Firefox, на `pnpm dev:mock` или стенде).

Матрица для каждого затронутого маршрута:

| Ширина | Темы | Состояния |
|---|---|---|
| 1440 (ноутбук) | светлая, тёмная | данные, пусто, ошибка |
| 820 (планшет, `pointer: coarse`) | светлая, тёмная | данные |
| 390 (телефон) — только главные экраны ролей | светлая | данные |

Состояния включаются параметром мока (`?mock=empty`, `?mock=error`). Файлы — `shots/<маршрут>/<ширина>-<тема>-<состояние>.png`, в git не коммитятся, прикладываются к PR.

Посмотри каждый скриншот глазами, рядом с макетом на холсте.

## 2. Чек-лист системы

- [ ] Цвета, шрифты, отступы, радиусы — только из системы. Нет новых оттенков, теней, радиусов.
- [ ] Одна кнопка с заливкой на экран. Необратимое действие выглядит иначе, чем обычное.
- [ ] Нормальное состояние без цвета; статус — иконка + метка, не только цвет.
- [ ] Иерархия читается без декоративных подписей: главное видно за 3 секунды.
- [ ] Пять состояний есть и совпадают с образцами `frontend-screens`.
- [ ] Числа, количества и время — через `format.ts`; табличные цифры ровные.
- [ ] Тёмная тема выглядит задуманной, а не инвертированной.
- [ ] Планшет: цели касания от 44 px, ничего не обрезано; телефон: главное действие доступно без горизонтальной прокрутки.
- [ ] Настоящие данные длинной длины не ломают раскладку (длинное название блюда, 6-значное количество).

## 3. Анти-slop

Slop — это выбор по привычке, а не для продукта. Подозрителен элемент, если несколько из этого верно: его можно вставить в чужой продукт без изменений; он повторяет знакомый «сгенерированный» шаблон; спорит с системой; не несёт ни информации, ни состояния, ни действия, ни смысла бренда.

Кластеры, которые выдают одну причину (по `no-ai-design-slop`):

| Кластер | Признаки |
|---|---|
| **Типовой AI SaaS** | надпись капсом с разрядкой над заголовком, огромный заголовок-предложение, фиолетовый градиент, свечения, стеклянные карточки, иконки в цветных плитках, bento-сетка, размытые тексты |
| **Апокалипсис карточек** | карточка в карточке, плашки-пилюли на всём, рамка и тень одновременно, крайние радиусы, всё в контейнерах вместо отступов |
| **Театр движения** | контент скрыт до анимации, одинаковые появления, пульсирующие статусы без живых данных, увеличение при наведении |
| **Фальшивая солидность** | моноширинные микроподписи, декоративная сетка на фоне, выдуманные метрики, «окно браузера» вокруг скриншота, технический текст без смысла для пользователя |
| **Чужой фрагмент** | блок с другим шрифтом, радиусом, акцентом или плотностью, чем остальной интерфейс |
| **Полировка вместо правды** | красивые эффекты при неясном тексте, слабых действиях, отсутствующих состояниях, сломанной адаптивности |

Пример: моноширинный капс в заголовках и «миллиметровка» на фоне — ровно кластер «фальшивая солидность». Если такое и есть сигнатура (решено в ADR-0002), оно живёт в одном-двух местах, а не на каждом экране.

### Тест удаления

Для каждого подозрительного элемента:

1. Назови точно: «надпись над заголовком», «карточка в карточке», «пульсирующая точка».
2. Какую работу он делает?
3. Мысленно убери. Если смысл, состояние, действие и характер остались, а ясность выросла — удали.
4. Если удаление что-то теряет — минимальная правка средствами системы.
5. Замену добавляй, только если она нужна. Не компенсируй новым эффектом.

Не заменяй отличительный выбор модным нейтральным шаблоном. Не убирай полезную плотность и асимметрию только потому, что они необычны.

## 4. Доступность

- [ ] `@axe-core/playwright` на каждом скриншоте данных: 0 нарушений уровня serious и critical.
- [ ] Клавиатура: Tab проходит по порядку чтения, фокус виден и не прячется под липкой шапкой, Escape закрывает диалог.
- [ ] У каждого поля подпись, у каждой кнопки-иконки `aria-label`.
- [ ] Заголовки без пропусков уровней, `h1` один.
- [ ] `prefers-reduced-motion`: анимаций нет, статичное состояние полное.
- [ ] Автотест контраста зелёный (`pnpm test`).

## 5. Блок в описание PR

```md
### Визуальная проверка
Макет: <ссылка на страницу холста>
Скриншоты: <вложения: 1440 светлая/тёмная, 820, 390>
- Система: ок / <что отступает от системы и почему>
- Анти-slop: удалено <что>, оставлено <что и зачем>
- axe: 0 serious/critical
- Клавиатура: ок
```

Итог — что убрано или исправлено и почему стало лучше. Без оценок «на вкус» и без догадок, писал ли это ИИ.

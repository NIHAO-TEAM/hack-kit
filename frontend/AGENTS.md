# AGENTS.md — frontend

Дополняет корневой [AGENTS.md](../AGENTS.md). Дизайн — отдельный критерий жюри и первое, что жюри видит. Направление дизайна — [ADR-0002](../docs/adr/), система — скилл `frontend-design-system`.

## Стек

Версии фиксируются точно в день 0 (последние стабильные на тот момент), обновляются только отдельным изменением.

| Что | Выбор | Почему |
|---|---|---|
| Основа | React + TypeScript (strict) + Vite, pnpm | |
| Роутинг | TanStack Router, маршруты файлами в `src/app/routes/` | Типизированные пути и параметры, загрузчики, guard-ы прав |
| Данные | TanStack Query | Кэш, повторы, сброс по ключу. Ключи — по правилам ниже |
| Компоненты | Mantine (core, notifications, dates) | Таблицы, модалки, тёмная тема через CSS-переменные, команда её знает |
| Формы | Mantine Form + zod | Правила предметной области — чистые функции в `model`, форма их не дублирует |
| Клиент API | `openapi-typescript` + `openapi-fetch` | Типы из `api/openapi.yaml`, руками не пишутся |
| Моки | MSW | Фронт работает без бэкенда, демо при упавшем API |
| Иконки | один набор (Tabler) через реестр `shared/ui/icon` | |
| Шрифты | локально через `@fontsource*` | Стенд не зависит от внешних CDN |
| Проверки | ESLint (typescript-eslint, react-hooks, плагины TanStack), Prettier, Stylelint, steiger (слои FSD) | |
| Тесты | Vitest + Testing Library + jsdom; Playwright (Firefox) для e2e и скриншотов | |

## Команды

```bash
pnpm dev               # разработка, API проксируется на backend
pnpm dev:mock          # разработка на MSW-моках, без backend
pnpm api:types         # типы из ../api/openapi.yaml → src/shared/api/schema.gen.ts
pnpm typecheck
pnpm lint && pnpm lint:styles && pnpm lint:fsd
pnpm test              # unit, включая автотест контраста
pnpm shots             # скриншоты по матрице (scripts/screenshots.mjs)
pnpm check             # всё перед PR: api:types без диффа, typecheck, линтеры, формат, тесты, сборка, check-built-css
```

## Структура

Feature-Sliced Design (облегчённый), подробно — скилл `frontend-architecture`.

```
src/
  app/        провайдеры, роутер и маршруты, оболочка, realtime, тема
  pages/      страница на маршрут: собирает виджеты и фичи
  widgets/    крупные блоки страницы (таблица склада, лента сигналов)
  features/   действия пользователя (принять поставку, закрепить блюдо)
  entities/   сущности: типы, query-ключи и options, форматтеры, мелкие UI
  shared/     api, ui (дизайн-система), lib (format, quantity, time), config
```

Импорты только вниз по слоям. У слайса публичный `index.ts`, глубокие импорты запрещены (steiger).

## Правила

- **Бизнес-логика только на бэкенде.** Фронт не пересчитывает остатки, сроки, стоп-лист, приоритеты: статус приходит с сервера, фронт выбирает вид.
- **Сначала макет.** Экран без макета на холсте не верстается: макет → согласование → верстка (скилл `frontend-design-direction`, раздел «Макет экрана»).
- **Только система.** Цвета, отступы, радиусы, шрифты — из темы. Hex, px вне шкалы и свои тени в компонентах запрещены. Не хватает компонента — добавь в `shared/ui` и на витрину `/dev/ui`.
- **У каждого экрана пять состояний:** загрузка, пусто, ошибка, нет связи, нет прав (скилл `frontend-screens`).
- **Роль видит своё.** Навигация и действия зависят от прав профиля (`can(point, 'right')`). Право, которого нет, — действие скрыто, раздел целиком — экран «Недостаточно прав».
- **Реальное время через SSE.** Сигнал называет категории, фронт сбрасывает ключи Query этих категорий. Изменившаяся строка коротко подсвечивается. Обрыв — плашка и метка «могли устареть».
- **Время — время стенда** (`GET /api/clock`), а не часы браузера.
- **Две темы с первого дня.** Новый экран проверяется в обеих.
- **Три ширины:** ноутбук 1440, планшет 820 (касание от 44 px), телефон 390 для главных экранов ролей.
- **Скриншоты в PR** по скиллу `frontend-design-review`.

## Скиллы

| Скилл | Когда |
|---|---|
| `frontend-design-direction` | день 0 — выбор направления; перед каждым новым экраном — макет |
| `frontend-design-system` | любая вёрстка и стили: токены, тема, компоненты, куда писать стиль |
| `frontend-screens` | новый экран или состояние: анатомия, пять состояний, формы, тексты, форматы |
| `frontend-architecture` | новый слайс, маршрут, запрос, право, сигнал SSE |
| `frontend-testing` | решить, нужен ли тест, и как его написать |
| `frontend-design-review` | перед PR: скриншоты, чек-лист анти-slop, доступность |

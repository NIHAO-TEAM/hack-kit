# r2_B. Скептик, раунд 2 (финал)

Проверено против `01_solution.md` вместе с правками `r1_author.md`. Скрипты лежат в scratchpad сессии, вне репозитория. `r2.py` — модель после правок: средний порог 50, `funds` по A P1-8, почасовая услуга даёт 720 списаний в окне `[asOf, asOf+H)`, P·R округляется до цента по каждой услуге, состояния `lost`/`unscored`. `r2_seeds.py` и `r2_mixed.py` прогоняют модель по 200 сидам `generate.py`, по другим объёмам, `--reference` и `--transactions`.

## 1. Вердикт: KEEP WITH CHANGES

Модель, разделение скора и денег, действие с ценой оставляем. Новых фактов против ядра нет. Но правки автора закрыли путь жюри «вход → PATCH». Путь «жюри меняет **данные**» остался незакрытым: на нём сломаются цифры, уровни и сам смысл PUT (раздел 4, П-1…П-3).

## 2. Топ-3 изменения

1. **Один источник правды и правило `asOf` для PUT.** Снимок без поля `asOf` замораживается на максимальной дате события в снимке, часы сервера не используются. Эмулятор меняет текущий снимок и не перезаписывает его своим. REST-адаптер по умолчанию выключен и никогда не затирает PUT. Исходные данные хранятся в схеме организаторов (`001_schema.up.sql`), триггеры шлют `NOTIFY` и запускают пересчёт, поэтому правка через `psql UPDATE` тоже видна вживую. CI: `PUT` файла `data.json` организаторов даёт ровно golden (3/2/1/4, 3879,73 €).
2. **Стенд — данные организаторов плюс 5–8 ручных аккаунтов с id ≥ 1001.** Набор `generate.py --accounts 200` не подходит: id и email совпадают с данными организаторов, 40 % аккаунтов без живых услуг, свежих `prolong_wait` нет ни одного. Первый экран должен показывать те же цифры, что слайд. Пароли прода не публикуются в README, есть кнопка «сбросить на данные организаторов».
3. **Процесс до этапа 3.** Переписать `.github/review-prompt.md` и `backend/AGENTS.md` под этот домен: убрать «точки» и запрет float, вписать инварианты модели. Первым изменением сделать одно блокирующее `!contract`, где уже есть все пути слоёв 1 и 2 (пути слоя 2 отвечают 501), и выбрать в нём генератор (ADR-0005). После этого `api/openapi.yaml` не трогает ни один параллельный PR.

## 3. Позиция по спорным

| | Позиция | Изменилась? |
|---|---|---|
| (а) k3s сразу или Compose + Caddy | **Compose + Caddy до контрольной точки (час 25), потом переключение на k3s.** Helm-чарт проверяется в CI на k3d (`helm install` + smoke), поэтому он не «бумажный». Compose обязателен по ТЗ, и прод на нём ничего не добавляет к работе. k3s до первой зелёной приёмки требует сразу реестр образов с pull-секретом, Ingress, cert-manager и лимит тела для PUT | нет, нового факта нет |
| (б) REST-адаптер | **Перенести в слой 3 или вырезать.** В ADR оставить интерфейс `Source`, эмулятор работает внутри приложения | **да.** Новый факт: ни 01, ни r1_author не задают приоритет между адаптером, который опрашивает полный список раз в N с, и `PUT /source/snapshot`. | (д) Открытый Swagger | **Открыт**, UI вшит в бинарь, в README фраза «открыт намеренно: в нём нет данных клиентов». `Try it out` на проде работает только после login | нет |

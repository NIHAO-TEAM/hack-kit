## Обязательные правки (входят в ADR-0001)

1. **Вход жюри.** `POST /auth/login` по паролю даёт полную сессию (cookie и Bearer); CSRF только для запросов с cookie. Учётка **`jury`** — все 11 путей по паролю, без второго фактора. Пароли и токен `/metrics` **не в публичном README**: передаём жюри отдельно (способ согласовать с организатором). `/metrics` открывается и по сессии вошедшего. CI: `login → PATCH settings → PUT snapshot → GET summary` одним паролем.
2. **Приёмка — слой 1.** Compose одной командой с данными и учётками; `openapi.yml` в репо и по HTTP; Swagger на `/api/v1/docs` вшит в бинарь, открыт без входа, «Try it out» — после Authorize; все 11 путей; `/metics` = `/metrics`. CI: маршруты = спека, Compose на чистой машине.
3. **Время модели.** `asOf` из тела снимка; без него — **максимум дат событий снимка**; часы сервера — только явной настройкой. `asOf` и пояс в шапке.
4. **Источник данных.** `PUT /source/snapshot` всегда главнее эмулятора и адаптера: после ручной загрузки опрос на паузе, пока его не включат. На экране «Источник» (слой 1) — правка одной услуги и загрузка файла.
5. **Деньги.** Три имени: ожидаемая потеря (Σ P·R), под угрозой (Σ R среднего и высокого), уже потеряно. Правила подсчёта — в спеке: окно `[asOf, asOf + H)`, почасовая — 720. `price_basis` — настройка. Прототип-оракул в репо, golden снимается с него. `bigint`/`int64`.
6. **Уровни.** Пороги 70 / 50. Отдельное состояние «потерян»; «нет оценки» — нет услуг или противоречивые записи.
7. **Изюминка — в слой 1** (C r2): два действия с ценой (тот же `Score()` на копии), полоса «удалит биллинг за 5 дней», таймер окна.
8. **Стенд.** Данные организаторов + 5–8 ручных аккаунтов с id от 1001 (B r2: `generate.py --accounts 200` переписывает услуги первых 10 и не даёт свежих `prolong_wait`). В ручных: свежие `prolong_wait` (1–3 дня), аккаунт без услуг, низкий риск. Кнопка «сбросить на данные организаторов».
9. **Контракт первым.** Одно изменение `!contract` со всеми путями слоёв 1 и 2 — первое на этапе 3; `api/openapi.yaml` защищён, иначе правки пойдут по одной.
10. **Три слоя.** Слой 1 — приёмка, модель, деньги, действия, SSE, `/metrics`, Compose; контрольная точка **приёмка зелёная на проде 24.10 ~20:00 (час 25)**. Слой 2 — k3s + Helm, Keycloak-OIDC, REST-адаптер, свой Prometheus, график оттока, ползунок «что если», `docs/model.md`. Слой 3 (отсечка 25.10 10:00) — Grafana, журнал, CSV, «в работе», k6 на 100k, Trivy.

## Цифры для питча (B r2: `asOf` 2026-10-19T15:00Z, 720 списаний, пороги 70/50) [ПРОВЕРЕНО прототипом]

- Уровни 3 / 2 / 1 / 4: высокие №10, 5, 9; средние №4, 1; низкий №6; потеряны №2, 3, 7, 8.
- Ожидаемая потеря **3879,73 €**, под угрозой 6900,46 €; №9 — 3459,27 € (89,2 %).
- Пополнить №9 на 529,84 € → **−1067,48 €**.
- Одно письмо «включите автопродление» №1 → **−365,29 €**, скор 56,02 → 41,57 (средний → низкий).
- `noauto` 0,55 → 0,85: №1 → 85,15, всего 4080,42 €.
- На питче продаём **метод** (действие с ценой), а не «89 %»: цена в генераторе случайна (`generate.py:59`).

## Остаётся [НАДЕЮСЬ] / нужен человек

- `price` у `hour` — за час? Вопрос эксперту не отправлен; от ответа зависит масштаб всех денег.
- VM (≥ 4 ГБ под Keycloak) и домен — владелец и срок назначает человек, нужно к часу 6.
- Пороги 70 / 50 устойчивы только на данных организаторов: на других сидах среднего уровня может не быть [ПРОВЕРЕНО B, 43 из 200 сидов]. Пороги редактируемы — это и ответ жюри.
- Процесс: `review-prompt.md` и `backend/AGENTS.md` содержат модель кита («точки», «без float») — править до этапа 3 (защищённые пути, нужно «да» человека). ADR-0001 заменяет модель «компания → точки → роли» (ADR-0003 кита).

# 01. Решение для дебатов: слияние 01a и 01b

Источники: `01a.md` (пахан, Opus 5.5, видел ответы эксперта), `01b.md` (Sonnet 5.5, свежий контекст, только `case.md` и данные), аудит `00_audit.md`. Ответы эксперта — `docs/experts/2026-10-23-aeza-chat.md`. Цифры на данных организаторов (`cases/analizator/data.json`, опорная дата `2026-10-19T15:00Z`) посчитаны прототипом 01b и пересчётом аудита; в Go они станут golden-тестом.

## Одной фразой

**«Контур удержания»** — внутренний сервис aéza: из биллинга по REST считает объяснимый риск каждого клиента, переводит его в ожидаемую потерю в евро за 30 дней и к каждому рискованному клиенту прикладывает **действие с ценой** («что сделать и сколько это снимет»). Встаёт в контур aéza (REST-биллинг, вход с TOTP и ключами доступа, Prometheus, Kubernetes) правкой `values.yaml`, без правки кода.

## Модель

**Время модели** `asOf`: по умолчанию — максимум `createdAt`/`performedAt` в снимке, а не `expiresAt` (у него бывают будущие даты) [ПРЕДПОЛОЖЕНО]; режим «реальные часы» — настройкой. Иначе к питчу 25.10 все сроки уедут на 6 суток.

**Живые услуги:** `active`, `suspended`, `prolong_wait`. `deleted` и `blocked` — «уже потеряно», в риск не входят [ПРЕДПОЛОЖЕНО].

| Признак | f ∈ [0, 1] | w по умолчанию |
|---|---|---|
| `pwait` — ожидает оплаты | 1 − осталось_до_удаления / 5 дн.; срок вышел → 1 и тег «статус устарел» | 0,80 |
| `funds` — не хватает средств | (нужно − есть) / нужно; нужно = списания по `active` и `suspended` за 7 дней + долг по `prolong_wait`; есть = `balance` + `bonusBalance` при `unlocked` | 0,70 |
| `noauto` — автопродление выключено | 1 − дней_до_окончания / 7, 0 при > 7 | 0,55 |
| `fail` — продления не проходят | доля `not_performed` среди `prolong` | 0,40 |
| `susp` — выключена клиентом, но оплачивается | 1 для `suspended`; с истёкшим сроком — тег качества данных | 0,35 |
| `flight` — деньги могут уйти | `withdrawBalance` / `balance` | 0,15 |

- Риск услуги P = 1 − Π(1 − wᵢ·fᵢ). Скор клиента = 100 · max P. Уровни: высокий ≥ 70, средний ≥ 45, иначе низкий; пороги редактируются.
- «Нет оценки» — нет живых услуг (клиенты 2, 3, 7, 8) [ПРОВЕРЕНО].
- `long_suspended` из 01a убран: даты перехода в `suspended` в данных нет (аудит №4). Длительность простоя копится по разнице снимков и включается, когда история появится.
- Признак — плагин: один Go-файл (`ID`, `Eval`, коэффициенты по умолчанию, шаблон причины), регистрация в реестре; настройки, API и панель подхватывают его сами. Пример ~25 строк в README.
- Проверки качества данных — тоже плагины, счётчики в `/metrics` и на экране «Источник».

## Деньги

- Выручка услуги за горизонт H = 30 дн.: R = `price` × число списаний в окне (почасовая — 720; `prolong_wait` — одно, долг; остальные — периоды, попавшие в окно).
- **Ожидаемая потеря** = Σ P · R — главное число, оно же в `/metrics`. Рядом: **под угрозой** = Σ R по среднему и высокому риску; **уже потеряно** — `deleted`/`blocked`.
- Пояснение на экране: «сумма запланированных платежей на 30 дней, взвешенная вероятностью их срыва; не входят новые клиенты, скидки, возвраты».
- Целые евроценты, float только на выводе.

## Изюминка

**Лента действий с ценой.** Для клиента высокого и среднего риска берём главную причину, применяем действие к копии данных, пересчитываем той же функцией.

| Действие | Клиент | Эффект (01b, на данных организаторов) |
|---|---|---|
| Пополнить или выдать промо на 538,39 € | №9 | потеря 3481 → 2401 €, **−1080 €** |
| Одно письмо «включите автопродление» | №1 | скор 56 → 42, потеря 383 → 18 €, **−365 €** |
| «К биллингу» | 10 услуг | экономии нет, но в рассылку не уходят |

Цифра на стенде: **«3900 € под угрозой за 30 дней; 89 % — у одного клиента; 365 € снимаются одним письмом»** [ПРОВЕРЕНО прототипом 01b; пересчитать Go-кодом после правки `funds` под аудит №3].

Таймер окна спасения в строке очереди («до удаления 2 д 7 ч») — из 01a.

| Роль | Экран | Глагол |

Демо-вход под ролью — только при `DEMO_MODE=true`, в проде выключен. Живое обновление — SSE `{version}`, изменившиеся строки подсвечиваются.

## Внешние участники

- **Биллинг aéza** — REST-опрос по курсору `updatedAt` и сверка раз в N минут; сбой источника не стирает оценку («данные от 12:40»). На стенде — эмулятор биллинга: двигает время и статусы, принимает кнопки «пополнить» и «включить автопродление». Формат их API нам неизвестен, адаптер — под наш контракт [ПРЕДПОЛОЖЕНО].
- **Prometheus aéza** — `/metrics` по Bearer-токену, `/metics` — алиас; `ServiceMonitor` в Helm.

## Видимая инженерия

- Прод: k3s на VM, Helm, публичный домен, TLS, наружу только 443, Postgres за NetworkPolicy, миграции Job-ом, 2 реплики. Grafana по логину, без анонимного доступа; дашборд в репо.
- Один слой результатов для панели, API и `/metrics`; тест: Σ `/metrics` = `/analytics/summary`.
- Нагрузка: `generate.py` → 100k аккаунтов, 300k услуг; k6; цель — пересчёт ≤ 3 с, p95 списка ≤ 200 мс [НАДЕЮСЬ]; `docs/load/`.
- Безопасность: argon2id, HttpOnly Secure SameSite-сессия, CSRF, лимит попыток, TOTP обязателен для аналитика и администратора, WebAuthn, CSP/HSTS, distroless non-root, `govulncheck`, Trivy, логи без email и балансов, журнал действий.
- Тесты: табличные по признакам; свойства (скор в 0–100, монотонен по весу); golden на наборе организаторов; права в API; e2e демо; запуск по README на чистой машине в CI.

## Демо за 5 минут

1. Публичный домен, вход маркетолога (пароль + TOTP или ключ доступа). Карточки: 3 высоких, 3 средних, 4 «нет оценки», потеря 3900 €.
2. Очередь по потере: №9, затем №1. Переключение на скор: №10, 5, 9 — почему деньги и скор расходятся. Карточка №9: причины, формула одной услуги, смысл суммы, действие «−1080 €».
3. Второе окно, аналитик: `noauto` 0,55 → 0,85, предпросмотр, применить — у маркетолога без перезагрузки №1 стал высоким.
4. Кнопка эмулятора «автопродление для №1»: риск падает, потеря снижается. `/metrics` и Grafana — те же числа. Перезапуск пода — настройки на месте.

## Не делаем

ML на синтетике; рассылки клиентам (инструмент внутренний); очереди сообщений (источник — REST); мультиарендность; интеграцию с Invoice Keeper — только после 100% бизнес-задачи и с записью в README.

## Открытые вопросы и допущения

- [ПРЕДПОЛОЖЕНО] `price` — цена за один период `paymentTerm` (у `hour` — за час): от этого зависит 99% денег. Первый вопрос эксперту.
- [ПРЕДПОЛОЖЕНО] `prolong_wait` не списывает деньги почасово, а ждёт одного платежа (долга).
- [ПРЕДПОЛОЖЕНО] `withdrawBalance` входит в `balance` (в данных всегда ≤).
- [ПРЕДПОЛОЖЕНО] `blocked` для маркетинга необратим.
- [ПРЕДПОЛОЖЕНО] Дата удаления для графика факта = `expiresAt` + 5 дн.
- [НАДЕЮСЬ] Пересчёт 100k за 3 с; Go совпадёт с прототипом до цента.
- Процесс: решение заменяет модель кита «компания → точки → роли» (`AGENTS.md`, ADR-0003) — нужно «да» человека в ADR-0001.

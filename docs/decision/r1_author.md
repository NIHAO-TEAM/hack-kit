# r1. Ответ автора (пахан)

Все трое: KEEP WITH CHANGES. Модель и действие с ценой никто не оспорил. Спор — о входе, объёме и подписях к деньгам. Ниже — позиция по каждой P0 и P1. «Принято» значит, что правка войдёт в `01_solution` после вердикта.

## P0

| Претензия | Кто | Позиция | Правка |
|---|---|---|---|
| Обязательный TOTP ломает вход жюри логином и паролем, `PATCH /model/settings` недоступен | A P0-1, B №1, C-2 | **Принято, опровергать нечем** | Пароль даёт полную сессию. Второй фактор — флаг пользователя; демо-учётки `marketer` и `analyst` в README без него, отдельная учётка `secure` показывает TOTP. `login` отдаёт cookie и Bearer; CSRF только для запросов с cookie; лимит попыток — по паре логин + IP. CI: `login → PATCH settings → GET summary` одним паролем |
| Приёмка не записана: Compose, OpenAPI, Swagger, 11 эндпоинтов | A P0-2 | **Принято** | Раздел «Приёмка» — слой 1, чек-лист 11 путей, `docker compose up` одной командой с данными и учётками, Swagger на `/api/v1/docs` вшит в бинарь и открыт без входа (данных клиентов в нём нет), спека отдаётся как `openapi.yml` и лежит в репо (`api/openapi.yaml` + копия `.yml`, CI сверяет). CI: маршруты = спека, Compose на чистой машине |

## P1: принято

| Претензия | Кто | Правка |
|---|---|---|
| Свой WebAuthn дорог и вне рубрики, OIDC в рубрике | B №5, C-3 | Ядро: пароль + свой TOTP (дёшево). Слой 2: OIDC через Keycloak в профиле Compose `sso` и в проде, настроенный как контур aéza: FIDO2/WebAuthn и TOTP на стороне IdP. Это закрывает бонус кейса и слова эксперта без своего крипто-кода. Свой WebAuthn — слой 3 или никогда |
| «Нет оценки» у ушедших клиентов | A P1-6, C-4 | Два состояния: **«потерян»** (все услуги `deleted`/`blocked`, сумма «уже потеряно») и **«нет оценки»** (нет услуг или противоречивые записи). В `/metrics` — `lost` и `unscored` раздельно. В расширенный набор — 1–2 аккаунта без услуг |
| «3900 € под угрозой» — на деле ожидаемая потеря; «под угрозой» = 6932 € | B №3 | Имена жёстко: **ожидаемая потеря** (Σ P·R), **под угрозой** (Σ R среднего и высокого), **уже потеряно**. В пояснении — разложение «стоимость услуг → × риск → покрыто балансом» (A P1-7) |
| 720 или 721 списание, правила подсчёта неоднозначны, golden из текста не воспроизводится | B №3 | Правила — в спеку: окно `[asOf, asOf + H)`, почасовая — 720; просроченная не-`prolong_wait` — одно списание в `asOf`, дальше шаг от `asOf`. Прототип-оракул (Python, `score.py` Скептика) кладём в репо как тестовый инструмент, golden снимаем с него |
| Цифра держится на случайной цене генератора (`generate.py:59`) и допущении «`price` за период» | A P1-7, B №3, C-1 | `price_basis: per_period | per_month` — настройка модели, видна рядом с суммой. Вопрос эксперту — сегодня. На питче продаём **метод** (действие с ценой, разделение скора и денег), а не «89 %» |
| `asOf` = max дат на 24 мин раньше опорной | B №6, C-10 | Поле `asOf` в теле снимка; без него — значение из настроек (по умолчанию «часы сервера»). Сид данных организаторов ставит `asOf = 2026-10-19T15:00Z`. `asOf` и пояс — в шапке, редактируемы |
| Низкого уровня нет, средний держится на шуме `fail` | B №4 | Средний порог 50: расклад 3 / 2 / 1 / 4 [ПРОВЕРЕНО Скептиком] |
| Таймер окна не тикает, стенд на 10 клиентах — игрушка | A P1-11, B №4, C-5 | Стенд: данные организаторов + расширенный набор (`generate.py` ~200 аккаунтов) + эмулятор, который порождает свежие `prolong_wait` (1–3 дня). Кнопка «сбросить на данные организаторов». Golden — на исходных 10. Полоса над очередью: «удалит биллинг в ближайшие 5 дней: N услуг, X €» |
| Объём не на 43 часа, допы вплетены в ядро | A P1-9, B №2, C-6 | **Три слоя с отсечкой.** Слой 1 (до часа 20): приёмка, модель, деньги, панель, SSE, `/metrics`, Compose. Контрольная точка — **приёмка зелёная на проде 24.10 ~20:00 (час 25)**. Слой 2 (до часа 36): прод k3s + Helm + TLS, действия с ценой, график оттока, OIDC/Keycloak, эмулятор и REST-адаптер, Grafana за входом, ползунок «что если». Слой 3 (если осталось, отсечка 25.10 10:00): журнал, CSV, «в работе», свой WebAuthn, k6 на 100k, Trivy. Всё вне обязательного — в разделе README «Дополнительно» |
| Две реплики, LISTEN/NOTIFY, гонки PATCH/snapshot | B №8, C-6 | Одна реплика, рассылка событий внутри процесса. Один воркер пересчёта с «грязным» флагом; результат помечен парой (`dataVersion`, `settingsVersion`); ответы несут `version`, фронт отбрасывает старые. Масштабирование — абзац в ADR |
| Приём 100k за 3 с нереален | B №7 | Две цели: пересчёт после PATCH на 100k ≤ 1 с; `PUT snapshot` 100k ≤ 30 с (потоковый разбор + `COPY`). Лимит тела в Ingress |
| int32 переполнится | B №9 | `bigint`, `int64`, `format: int64`; P·R округляем до цента один раз на услугу |
| Имена полей в снимке (опечатки кейса) | A P1-3 | Тело = форма `data.json`, имена схемы; алиасы опечаток (`pice`, `paymentTem`, `quater_year`, `pefomed`, `autoprolong`) принимаются молча, в ответах — имена схемы. Тест на оба варианта |
| Состав метрик и доступ сборщика | A P1-4, C-7 | `churn_customers{level=high|medium|low|unscored|lost}`, `churn_expected_loss_cents`, `churn_at_risk_cents`, `churn_lost_cents`, `churn_recalc_duration_seconds`, `churn_snapshot_age_seconds`, HTTP. `/metics` = `/metrics`. Токен в материалах сдачи; на проде свой Prometheus со статическим `scrape_config`, target UP |
| Кто достаёт VM и домен, запасной путь | A P1-10, B №2 | Владелец — человек, срок — до часа 6 (01:00 24.10). Запасной путь: одна VM, Compose + Caddy с TLS; Helm-чарт в репо при любом исходе |
| Изменить данные на проде для жюри | A P1-12 | Эмулятор в проде доступен аналитику, подписан «имитация биллинга»; на экране «Источник» — правка одной услуги и загрузка файла; `curl` для `PUT snapshot` в README |
| Swagger за логином или нет | A P1-13 | Открыт (см. P0-2), решение записано в README |

## P1 и P2: частично или нет

| Претензия | Кто | Позиция |
|---|---|---|
| Прод сразу на Compose + Caddy, k3s по остатку | B №2 | **Частично.** Эксперт прямо сказал «кубер», и Helm — то, что жюри aéza проверит руками. Если VM есть к часу 6, прод сразу на k3s (один узел, Traefik из коробки, cert-manager). Если нет — Compose + Caddy, k3s в слое 2 |
| REST-адаптер с курсором можно вырезать | B, порядок резки 4 | **Оставляем в слое 2.** Это единственный ответ эксперта про источник («рест апи»). Упрощаем: опрос полного списка раз в N секунд и сравнение, курсор `updatedAt` — если успеем |
| Grafana не принесёт баллов | C-6 | **Оставляем в слое 2**, но лёгкой: один дашборд из провижининга за входом. Эксперт: инфраструктура — «да, но в проде и секьюрно» |
| Тег «к биллингу» как вывод о реальном биллинге | A P2-19 | Принято: подаём как правило, «на данных организаторов срабатывает 10 раз» |
| Причина и деньги из разных услуг | B №11 | Принято: в очереди по потере главная причина и действие — из услуги с наибольшим P·R |
| Ползунок «что если» на одном экране | C | Принято в слой 2: ползунок вызывает `dryRun` вживую, «применить» сохраняет |
| Расширяемость показать реальным PR | C-9 | Принято: признак `flight` добавляется отдельным PR, ссылка на его diff в README |
| Валидация настроек, SSE за прокси, сортировка «нет оценки», границы времени | A P2-16..20, B №10 | Принято целиком, это мелкие правки слоя 1 |

# Правила модели риска оттока

Единственный источник правил подсчёта. Эталонная реализация — `tools/oracle/oracle.py`, числа — `testdata/golden/`. Правка правила без правки оракула и golden не допускается (`python3 -I tools/oracle/oracle.py --check` падает). Все примеры — набор организаторов `cases/analizator/data.json`, `asOf = 2026-10-19T15:00:00Z`, настройки по умолчанию. Деньги — целые центы.

## 1. Время

`asOf` задаётся явно, часы системы не читаются. Окно списаний — `[asOf, asOf + H)`; `H = 720` ч для денег, `H = 168` ч для запаса средств.

## 2. Живые услуги и состояния клиента

- Живые: `active`, `suspended`, `prolong_wait`. Остальные (`deleted`, `blocked`) — не живые.
- Нет услуг вообще → состояние `unscored`, скора нет.
- Услуги есть, ни одной живой → `lost`, скора нет, считается только «уже потеряно».
- Иначе → `scored`.

Пример: клиент 2 — `lost`; клиент 7 — `lost`, уже потеряно 6 808,74 €.

## 3. Число списаний услуги в окне

- `prolong_wait` — 1 (долг, цена продления).
- `hour` — `H` списаний (720 за 30 дней, 168 за 7 дней).
- Остальные периоды (`week`, `month`, `quarter_year`, `half_year`, `year`): считается шагами периода от `base = max(expiresAt, asOf)`. Списание в `base + k·период` (k = 0, 1, …) попадает в окно, пока меньше `asOf + H`. Месяцы — календарные, день не больше последнего дня месяца.

Пример: услуга 9 (клиент 9, `month`, `suspended`, `expiresAt = 2026-09-09T15:00Z` — в прошлом): `base = asOf`, 1 списание за 720 ч и за 168 ч. Услуга 21 (`month`, `expiresAt = 2026-11-19T14:30Z`, позже `asOf + 720 ч`): 0 списаний. Услуга 1 (`hour`): 720 за 720 ч, 168 за 168 ч.

## 4. Деньги услуги `R`

`R = price × списания(720 ч)`. Настройка `priceBasis = per_month` (по умолчанию `per_period`): у `hour`-услуги `price` берётся за 720 часов, `R = price`, в запасе средств — `round(price · 168 / 720)`.

Пример: услуга 1: `95 × 720 = 68 400` центов (684,00 €).

## 5. Признаки (`f ∈ [0, 1]`)

| Признак | Когда есть | Формула |
|---|---|---|
| `pwait` | `prolong_wait` | `left = expiresAt + 5 дн − asOf`; `left ≤ 0` → 1, иначе `1 − left/5 дн` |
| `funds` | у услуги, у которой в окне 168 ч есть списание (`prolong_wait` или `списания(168 ч) > 0`); «нужно» и «есть» — на аккаунт | `нужно = Σ price × списания(168 ч)` по `active`, `suspended` `+ Σ price` по `prolong_wait`; `есть = balance + bonusBalance` при `bonusState = unlocked`, иначе `balance`; `f = max(0, (нужно − есть)/нужно)`, `нужно = 0` → 0 |
| `noauto` | `autoProlong = false` | `дни = (expiresAt − asOf)`; `дни > 7` → 0, иначе `min(1, 1 − дни/7)` (срок прошёл → 1) |
| `fail` | всегда | доля транзакций `type = prolong` услуги со статусом `not_performed`; транзакций нет → 0 |
| `susp` | `suspended` | 1 |
| `flight` | всегда, на аккаунт | `withdrawBalance / balance` — доля реферального баланса, доступная к выводу; `balance = 0` → 0. Вес по умолчанию 0 |
| `bonus_locked` | `bonusBalance > 0`, `bonusState = locked`, `нужно > есть` | 1 (иначе признак не применим); вес по умолчанию 0 |

Примеры: услуга 1: срок через 30 мин → `noauto = 1 − 0,0208/7 = 0,997024`; клиент 1, `flight = 14 592/83 810 = 0,174108`; клиент 9: нужно 144 490, есть 91 506 (бонусы закрыты) → `funds = 0,366697` (у каждой его услуги со списанием в окне; у услуги `year`, продлевающейся через 25 дней, `funds` нет, хотя аккаунт тот же); услуга 10 (клиент 10): срок вышел давно → `pwait = 1`.

## 6. Вероятность и скор

Веса по умолчанию: `pwait 0,80`, `funds 0,70`, `noauto 0,55`, `fail 0,40`, `susp 0,35`, `flight 0` (признак считается и виден в карточке, на скор не влияет, пока аналитик не включит вес; `withdrawBalance` — доступный к выводу реферальный баланс, факта вывода в данных нет), `bonus_locked 0`.

`P = 1 − Π(1 − wᵢ·fᵢ)` по присутствующим признакам услуги (шумовое ИЛИ). Скор клиента = `100 · max P` по живым услугам, округление до 2 знаков.

Пример: клиент 1 — скор 54,84; клиент 9 — 86,95; клиент 10 — 94,60.

## 7. Уровни

`high` — скор ≥ 70; `medium` — ≥ 50; иначе `low`. Пример: клиент 10 — `high`, 4 — `medium` (61,00), 6 — `low` (40,00).

## 8. Деньги клиента и сводка

- Ожидаемая потеря клиента = `Σ round(P · R)` по живым услугам (округление до цента на каждую услугу, затем целые). Пример: клиент 9 — 3 189,10 €.
- Под угрозой = `Σ R` по живым услугам клиентов `high` и `medium`.
- Уже потеряно = `Σ price × списания(720 ч)` по не живым услугам, как если бы они были `active`.
- Сводка: `expectedLossCents` = Σ потерь клиентов; `exposureCents` = Σ под угрозой; `lostCents` = Σ уже потеряно.

Пример: ожидаемая потеря 3 599,07 € (359 907), под угрозой 6 900,46 € (690 046), уже потеряно 7 368,34 € (736 834); уровни: high 3 (10, 5, 9), medium 2 (4, 1), low 1 (6), lost 4 (2, 3, 7, 8).

## 9. Действия с ценой

Действие применяется к копии данных клиента; эффект = ожидаемая потеря после − до (отрицательный — выгода). Скор и уровень пересчитываются.

- «Пополнить» — если `funds > 0`: сумма `нужно − есть` добавляется к `balance`. Пример: клиент 9 — пополнить на 529,84 € (52 984), эффект −1 027,49 € (−102 749).
- «Включить автопродление» — если `noauto > 0`: у всех услуг клиента `autoProlong = true`. Пример: клиент 1 — скор 54,84 → 40,00 (`low`), эффект −375,08 € (−37 508).

Цена действия `costCents`: у «Пополнить» — сумма пополнения, у остальных 0. «На каждый €» = `−эффект ÷ цена` с двумя знаками, при цене 0 пусто. Пример: клиент 9 — 102 749 ÷ 52 984 ≈ 1,94.

Сочетание `actionComboCents` — если применимо два действия и больше: действия применяются подряд к копии данных (сначала автопродление, затем пополнение «нужно − есть» по данным после автопродления), эффект считается пересчётом, а не суммой эффектов. Пример: клиент 9 — −1 029,32 € (−102 932) против суммы −1 028,84 €.

## 10. Формат golden

```
{asOf, source, settings, customers: [{id, state, score, level, expectedLossCents, exposureCents, lostCents,
  features: {serviceId: {признак: f}}, actionComboCents?, actions: [{type, amountCents?, costCents, lossDeltaCents, scoreBefore, scoreAfter, levelAfter}]}],
 summary: {levels, expectedLossCents, exposureCents, lostCents}}
```

`score` — число с 2 знаками или `null` (`lost`, `unscored`); деньги — целые центы; признаки — до 6 знаков.

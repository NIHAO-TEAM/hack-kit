## Разбивка на этапы

**Статус этапа** (последний столбец):

| Статус | Что значит | Кто меняет |
|---|---|---|
| ожидает | этап в плане, работа не разрешена | пахан предлагает |
| утверждён | работа по этапу разрешена: изменения из столбца «Изменения» запускаются сами (`assign.yml`, лимит исполнителей из `team.md`), когда слиты все изменения этапов из «Зависимостей» | пахан, по «да» человека на запуске или после сессии эксперта |
| в работе | хотя бы одно изменение этапа идёт; работа по-прежнему разрешена | пахан |
| готов | все изменения слиты, результат виден на стенде | пахан |
| сдвинут | отложен, новые изменения не запускаются | человек |

Ручного слияния нет (решение владельца 23.10): на запуске пахан по «да» человека утверждает весь план, дальше этапы идут сами по «Зависимостям» (`этап N`), ночью тоже. Изменение, которого нет в строке утверждённого этапа, ждёт метку `go:<id>` от человека.

`!` перед именем изменения (`` `!orders-contract` ``) — блокирующее: контракт, миграции, общие сценарии. Остальные изменения этапа запускаются только после его слияния. Обычно `!` одно на этап; если их несколько, они идут по порядку строки: каждое ждёт только предыдущие.

Размер этапа — до 8 часов (ночной — до 12). Размер изменения внутри — 1–3 часа. Последние 4 часа — фриз. Слои работ — `03_verdict.md`, правка 10: слой 1 — этапы 2–5, слой 2 — этап 6, слой 3 — этап 7.

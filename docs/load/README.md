# Замеры нагрузки

Образец — «Остаток» (2 место UMIRHack 2026): таблица сценариев с RPS, p95 и ошибками, плюс честная оговорка о железе.

## Сценарии

| Сценарий | Что доказывает |
|---|---|
| Чтение главного списка, кэш вкл/выкл | Быстро отвечаем на самый частый запрос |
| N одновременных записей на M штук остатка | Ровно M успешных, остальные — понятный отказ, в минус не ушло |
| Смешанная нагрузка 60 с | 0 ошибок 5xx, p95 |

Плюс тест свойств в CI (как `TestStockStaysConsistentUnderLoad` у Goden): после нагрузки остаток равен пересчёту с нуля. Он проверяет свойство, а не число.

## Нагрузка 100k клиентов (`load-k6`)

Сценарии — в `docs/load/k6/`. Цели из вердикта дебатов: пересчёт после `PATCH /model/settings` на 100k ≤ 1 с, `PUT /source/snapshot` на 100k ≤ 30 с.

### Результаты

Первый реальный прогон: [2026-10-23-load-100k.md](2026-10-23-load-100k.md) (стенд на раннере GitHub, 4 vCPU, workflow `deploy-load.yml`). Цели пока не достигнуты, числа ниже честные.

| Сценарий | Цель | Результат |
|---|---|---|
| `PUT /source/snapshot`, 100k | ≤ 30 с | ~44 с (42–45 с) |
| `PATCH /model/settings` → пересчёт | ≤ 1 с | ответ PATCH 2,6 мс; пересчёт по метрике сервера ~15 с |
| `GET /customers` с сортировкой, p95 (10 VU) | зафиксировать | 1,78 с, 0 % ошибок |
| `GET /analytics/summary`, p95 | зафиксировать | общий p95 чтения 453 мс (отдельно не выделен) |

Прогон повторяется вручную: Actions → «Deploy load» → Run workflow. Там же job «prod-read» (только чтение по проду, ≤ 5 VU).

### Как повторить

```sh
python3 cases/analizator/generate.py --accounts 100000 --services 300000 --transactions 1000000 --out /tmp/load
cp .env.example .env   # задать POSTGRES_PASSWORD, ADMIN_PASSWORD, SOURCE_TOKEN, METRICS_TOKEN
docker compose up -d
k6 run -e SOURCE_TOKEN=… -e SNAPSHOT=/tmp/load/data.json docs/load/k6/snapshot.js
k6 run -e PASSWORD=$ADMIN_PASSWORD docs/load/k6/read.js
k6 run -e PASSWORD=$ADMIN_PASSWORD -e METRICS_TOKEN=… docs/load/k6/recalc.js
```

Повторить второй раз: числа должны совпасть ±20 %. Время пересчёта по версии сервера — метрика `churn_recalc_duration_seconds`.

### Оговорки

- Замер на одной машине: k6, приложение и PostgreSQL делят процессор. Это порядок величин, а не обещание для боевого сервера.
- Генератор детерминирован (`--seed 42`), данные синтетические.
- Сценарии входят один раз в `setup()` и ходят с Bearer-токеном: вход ограничен по числу попыток (429).

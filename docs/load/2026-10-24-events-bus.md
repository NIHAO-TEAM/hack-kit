# Замер: шина событий без общей блокировки

Изменение `events-bus-fanout`. Было: `Publish` держал общий `sync.Mutex` на всё время рассылки. Стало: список подписчиков темы — неизменяемый срез под `atomic.Pointer`, `Publish` читает его без общей блокировки; на подписчика — свой `RWMutex`, защищающий канал от записи после закрытия.

## Условия

- **Не стенд GitHub.** Контейнер разработки: 4 vCPU Intel Xeon @ 2,1 ГГц, Go 1.24.7, Linux. Замер синтетический, внутри одного процесса, без сети и базы.
- Подписчики читают канал в своих горутинах (`drain`), поэтому буфер не копится и потерь в замере почти нет: мерится стоимость рассылки.
- Команда (до и после одна и та же; файл `bench_test.go` добавлен отдельным коммитом до правки шины):

```sh
cd backend
go test ./internal/platform/events -run xxx -bench . -benchmem -cpu 4 -count=3
```

## Результат (ns/op, три прогона; в скобках медиана)

| Бенчмарк | До | После | Выигрыш по медиане |
|---|---|---|---|
| Publish1Subs | 155 / 136 / 169 (155) | 117 / 105 / 126 (117) | −25 % |
| Publish100Subs | 21 959 / 22 462 / 22 982 (22 462) | 16 797 / 16 619 / 16 048 (16 619) | −26 % |
| Publish1000Subs | 249 666 / 265 498 / 252 512 (252 512) | 172 440 / 210 376 / 207 239 (207 239) | −18 % |
| PublishParallel (100 подписчиков, 4 издателя) | 19 948 / 21 103 / 19 867 (19 948) | 13 476 / 11 696 / 12 923 (12 923) | −35 % |

Аллокации на `Publish` — те же (0 для одного издателя, 1 для параллельного: упаковка значения в `any` в самом бенчмарке).

## Что это значит

- Рассылка одному событию стоит линейно от числа подписчиков (≈ 0,2 мкс на подписчика): основная цена — отправка в канал, а не блокировка. Поэтому однопоточный выигрыш скромный (18–26 %).
- Заметнее выигрыш у параллельных издателей (−35 %): они больше не выстраиваются в очередь на общей блокировке.
- Правка не меняет политику для медленного подписчика: издатель не ждёт, теряется самое старое событие. Новое — потери видны: `churn_events_dropped_total{topic}`; число подписчиков — `churn_events_subscribers{topic}`.
- Буфер SSE-потока оставлен прежним (16): замер выше его не затрагивает (подписчики успевают читать), основания менять нет. `SubscribeBuf` позволяет задать размер, когда они появятся.

## Проверка гонок

`TestPublishWhileSubscribeCancel`: 8 издателей публикуют, пока 10 горутин по 100 раз подписываются и отписываются (1 000 подписок); `go test -race -count=50` — без паник «send on closed channel» и без гонок.

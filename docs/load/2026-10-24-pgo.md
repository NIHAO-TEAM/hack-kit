# PGO: бенчмарки до и после

Дата: 24.10. Go 1.24.7, 4 vCPU Xeon 2.3 ГГц, `-benchtime 3x -count 10`, `benchstat`.
До: `-pgo=off`. После: `-pgo=backend/cmd/api/default.pgo`.

Профиль снят с `BenchmarkRecalc10k`, `BenchmarkRecalc100k`, `BenchmarkPublish*` (шина событий) и `BenchmarkObserve100`, слит через `go tool pprof -proto`; размер 54 КБ. Повторить — README, «Профиль сборки (PGO)».

## Результат

| Бенчмарк | до | после | изменение |
|---|---|---|---|
| Recalc10k | 66,87 мс ± 5 % | 62,50 мс ± 8 % | −6,5 % (p=0,015) |
| Recalc100k | 829,2 мс ± 5 % | 754,2 мс ± 5 % | −9,0 % (p=0,000) |
| Recalc100k, аллокаций | 8,533 млн | 7,960 млн | −6,7 % |
| Recalc100k, байт/оп | 852,3 МиБ | 833,2 МиБ | −2,2 % |
| Publish100Subs | 17,3 мкс ± 75 % | 13,1 мкс ± 41 % | в пределах шума |
| PublishParallel | 36,3 мкс ± 44 % | 37,4 мкс ± 21 % | в пределах шума |

Вывод: пересчёт быстрее на 6–9 %, шина событий без изменений (шум). Оставляем PGO и `GOMEMLIMIT`.

## Оговорки

- Профиль и замер сняты на одной нагрузке (синтетический снимок, seed 11), поэтому выигрыш на реальном потоке может быть меньше.
- Бенчмарка списка клиентов в репозитории нет, его не мерили и в профиль он не входит. Добавить — отдельное изменение.
- Шум шины событий большой (±40–75 %): её цифрам верить нельзя, только пересчёту.

## GOMEMLIMIT

`GOGC` не менялся, без замера. `GOMEMLIMIT`: Helm — `400MiB` (80 % от лимита пода 512Mi), Compose — `1GiB`, переопределяется в `.env`. Пересчёт 100k выделяет ≈ 833 МиБ за прогон, но живой набор меньше; влияние предела на пики GC в нагрузочном прогоне на стенде не мерили.

# Замер: пересчёт модели на всех ядрах

Бенчмарки `BenchmarkRecalc10k` и `BenchmarkRecalc100k` считают `risk.Score` по синтетическому снимку (`tools/snapgen`, seed 11) без чтения БД и разбора JSON: это чистое время расчёта.

## Условия

- **Не стенд GitHub.** Контейнер разработки, 4 vCPU (Intel Xeon 2,1 ГГц), Go 1.24.7, `GOMAXPROCS=4`. Числа показывают порядок величин, а не гарантию: на другом железе будут другими.
- Команда: `cd backend && go test ./internal/app -run xxx -bench 'Recalc' -benchmem -benchtime 10x`
- Профиль: добавить `-cpuprofile cpu.out -memprofile mem.out`, смотреть `go tool pprof -top -cum cpu.out`.

## Результат

| | до (3 прогона) | после (10 прогонов) |
|---|---|---|
| `BenchmarkRecalc10k` | 80,6 мс · 85,0 МБ · 794 397 выделений | 84,7 мс · 85,0 МБ · 794 405 выделений |
| `BenchmarkRecalc100k` | 947 мс · 842,5 МБ · 7 928 251 выделений | 848 мс · 842,5 МБ · 7 928 237 выделений |

Размер пачки (100k, после): 64 — 789 мс, 256 — 808 мс, 512 — 780 мс, 1024 — 787 мс. Разница между размерами в пределах разброса прогонов, взят `DefaultBatchSize = 256` из диапазона дизайна.

## Что это значит

- Расчёт на 100k клиентов уже укладывался примерно в 1 с: параллельность по клиентам появилась раньше (#131). Новый конвейер (пачки, пул воркеров, запись по индексу) на скорость расчёта почти не влияет: разница 10k/100k «до» и «после» — в пределах разброса измерений. Цель «≤ 1 с на 4 vCPU» достигнута и до правки; 15 с, замеренные на стенде 23.10, складываются из чтения и разбора снимка (`docs/load/2026-10-24-snapshot-stages.md`), а не из расчёта.
- Выигрыш этого изменения — **отмена**: новый снимок или настройки обрывают идущий расчёт между пачками, и сразу стартует новый по свежим данным. Раньше устаревший прогон дорабатывал до конца впустую.
- `sync.Pool` не добавлен. Выделения (843 МБ на 100k) структурные: срезы результата на услугу и на клиента (`scoreService`, `scoreCustomer`, `actionResults`, `scoreWith`), они уходят в итог и переиспользованы быть не могут. Горячего временного буфера профиль не показал, вслепую пул не ставили.

## Как снять профиль на сервере

`GET /debug/pprof/` (например `/debug/pprof/profile?seconds=30`, `/debug/pprof/heap`) с заголовком `Authorization: Bearer $METRICS_TOKEN`. Пользовательская сессия и роли маршрут не открывают, без токена — `401`. Маршрута нет в контракте и Swagger.

```bash
go tool pprof -http=:0 -H "Authorization=Bearer $METRICS_TOKEN" https://<хост>/debug/pprof/profile?seconds=30
```

Метрики конвейера: `churn_recalc_workers`, `churn_recalc_cancelled_total`, `churn_recalc_batch_seconds` (гистограмма длительности пачки).

## Принятые значения (до замера)

Основание — `docs/load/2026-10-24-recalc-bench.md`: пересчёт 100k выделяет ≈ 843 МБ за прогон (сумма аллокаций, не живая куча). [ПРЕДПОЛОЖЕНО] Живая куча 100k ниже этой суммы, пик RSS ≤ ≈ 1,1 ГБ, поэтому лимит приложения 1536 МиБ (запас 30 % от ≈ 1,2 ГБ); `requests` 512 МиБ.

| Параметр | Было | Стало |
|---|---|---|
| Приложение, limits.memory | 512 МиБ | 1536 МиБ |
| Приложение, requests | 128 МиБ / 100m | 512 МиБ / 250m |
| PostgreSQL, limits.memory | 512 МиБ | 2 ГиБ |
| PostgreSQL, requests | 128 МиБ / 100m | 768 МиБ / 250m |
| `shared_buffers` | 128 МБ | 512 МБ (25 % лимита) |
| `effective_cache_size` | 4 ГБ (умолч.) | 1536 МБ (75 % лимита) |
| `max_wal_size` | 1 ГБ | 4 ГБ |
| `checkpoint_completion_target` | 0,9 | 0,9 (задано явно) |
| `wal_compression` | off | on |
| `work_mem` | 4 МБ | 16 МБ |
| `max_connections` | 100 | 100 (задано явно) |
| `DB_MAX_CONNS` (пул) | max(4, NumCPU) | 16, `MaxConnLifetime` 30 мин |

`fsync` и `full_page_writes` не менялись. Compose (прод и dev) получил те же параметры PostgreSQL; `mem_limit` — приложение 1536m и PostgreSQL 2g в проде.

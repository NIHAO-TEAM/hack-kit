# Залп событий на 100 000 клиентов

Один прогон, где всё идёт сразу: большой портфель, залп событий, параллельные читатели очереди и живые SSE-клиенты. Проверяется, что ничего не упало и ни одно событие не потеряно (ADR-0004, п. 3 и 6).

> **Числа ещё не получены.** В среде, где сделано изменение, нет Docker и k6, поэтому первый прогон — ручной запуск `Deploy burst` на `main` (Actions → Deploy burst → Run workflow). Таблица ниже заполняется из артефакта `burst` этого запуска; пока в ней прочерки, чисел из головы здесь нет.

## Условия

- **Раннер** `ubuntu-latest` (4 vCPU, 16 ГБ — тот же, что в замере 100k; точные значения пишет шаг «Железо» в summary запуска). Сервер, PostgreSQL, k6 и сам скрипт делят процессор.
- Портфель: `cases/analizator/generate.py --accounts 100000 --services 300000 --transactions 1000000`, снимок грузится через `PUT /source/snapshot`.
- Залпы по очереди: 3 000, 10 000, 50 000 событий, `POST /source/emulator/stream` со `ratePerSecond=0`, зерно 1.
- Параллельно на каждый залп: k6 `burst-read.js` (20 VU читают очередь, 2 VU — сводку) и `sse.js` (500 SSE-клиентов, окна по 10 с).

## Команды

```sh
# На стенде GitHub: Actions → Deploy burst (workflow_dispatch; сам идёт после успешного Deploy smoke на main).
# Локально, для показа (Compose поднят, снимок 100k загружен):
ADMIN_PASSWORD=… METRICS_TOKEN=… make burst            # 3 000, 10 000, 50 000
ADMIN_PASSWORD=… METRICS_TOKEN=… make burst N="3000"   # один залп
```

## Что проверяется (красный, если нарушено)

| Проверка | Как |
|---|---|
| 0 ответов 5xx | рост `churn_http_request_duration_seconds_count{code=~"5.."}` за залп |
| применено + отклонено = отправлено | `report.applied + report.failed = events` |
| согласованность с пересчётом с нуля — 0 центов | `report.consistency.ok` и `diffCents = 0` |
| процесс не перезапускался | `process_start_time_seconds` не изменился, `restartCount` контейнера прежний |
| 0 обрывов SSE | метрика `sse_drops` k6: ответ `/events` пришёл раньше конца окна |
| 0 ошибок чтения очереди | доля `http_req_failed` в `burst-read.js` |

## Оговорки

- Это порядок величин на одном раннере, а не обещание для боевого сервера.
- k6 не отдаёт тело потока по частям, поэтому SSE-клиент проверяет, что поток **жив всё окно**, а не читает события; доставку считает сервер (`consistency`) и счётчик потерь шины `churn_events_dropped_total`: его прирост за залп попадает в `burst-N.json` и столбец «потеряно шиной». В проверки он не входит — шина вправе сбрасывать события медленным клиентам, число показываем.
- Таймаут прогона потока — 15 минут (`streamRunTimeout`); если 50 000 событий в него не уложатся, залп завершится ошибкой и это будет видно в итоге.
- Пик памяти и горутин — по `/metrics` раз в секунду; короткий всплеск между замерами может быть не пойман.
- По проду залп не гоняем: он сбрасывает данные эмулятора.

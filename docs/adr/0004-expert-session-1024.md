# ADR-0004: итоги сессии эксперта aéza 24.10

Статус: принято (Onisar, 24.10.2026: сообщение владельца в сессии пахана после экспертной сессии 17:00 МСК; `[lead]`)
Дата: 2026-10-24

## Контекст

Эксперт aéza на сессии 24.10 (17:00 МСК) сообщил (со слов владельца, дословных слов эксперта у пахана нет):
1. Внедрять CRM для маркетолога не нужно, это минус.
2. Invoice Keeper и наш кейс — совершенно разные продукты, второй больше для внутренних сотрудников.
3. Нужно прогнать тест на 2–3 тысячах событий пользователей и показать это.
4. Логотип aéza использовать можно, организаторы разрешили; делать продукт «под aéza».
5. Нужно глубже уйти в наш кейс.

## Решение

1. **CRM не делаем.** На вопрос, оставлять ли цикл «взять в работу» в главном демо, эксперт ответил: CRM будет минусом, не надо (подтверждено владельцем 24.10). Из интерфейса убираем весь цикл: экран «Задачи», сроки и напоминание в шапке, колонку «Работа», блок «Работа с клиентами», кнопки «Взять в работу», «Связались», «Отложить», «Закрыть» и блок наблюдения биллинга после взятия в работу. Данные и API задач на сервере остаются (для будущей калибровки), но интерфейса у них нет. Главное демо: очередь → карточка (причины, потеря, действие с ценой) → модель вживую → поток событий. Изменение `retention-crm-cut`.
2. **Invoice Keeper не делаем.** ADR-0001 остаётся в силе: одна организация, один кейс; объединение с Invoice Keeper снимается с плана, а не откладывается.
3. **Поток 2–3 тысяч событий** прогоняем и показываем: панель на экране «Источник» (`events-stream-emulator`) и тест с отчётом в `docs/load/` (`events-load-proof`).
4. **Логотип aéza разрешён.** Заменяет в ADR-0003 пункт «Не используем» в части логотипа-надписи и названия «aéza» в интерфейсе. Использовать только официальный файл (`https://aeza.net/logo.svg`, скачан 24.10; присланный владельцем самодельный SVG не используем), без правок цвета, формы и пропорций, с охранным полем по брендбуку (`aeza-full-brand`). Маскота и самодельные версии не используем. Название продукта остаётся «Контур удержания».
5. **Углубляемся в кейс**, а не вширь: потеря по причинам (`loss-by-reason`), сравнение действий с ценой (`action-compare`), устойчивость очереди к весам (`model-sensitivity`). Новые функции вне кейса не берём.

## Последствия

- Проще: продукт ближе к кейсу «кого спасать и на сколько это денег»; демо без лишнего «CRM».
- Сложнее: демо-сценарий, README и `Demo e2e` переписываются; тесты удалённых экранов удаляются как следствие решения, а не ослабление гейта.
- Требует от человека: подтвердить у организаторов, что `aeza.net/logo.svg` подходит (вопрос 3 в документе сессии).

## Отброшено

| Вариант | Почему нет |
|---|---|
| Оставить экран «Задачи» «для полноты» | эксперт назвал CRM минусом |
| Удалить задачи и API на сервере | теряем данные для калибровки; хватает убрать интерфейс |
| Объединить с Invoice Keeper | разные продукты по словам эксперта |
